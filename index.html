Cella Lang

A formalization engine that says what it checked.
What is Cella?Open the editorUse it from JavaScript

Proofs, verification, many type theories and solvers in one engine, with the Cella language as their common protocol.

Try it

Section titled “Try it”

Three examples for different readers: switching tabs runs the example, and the verdict and output appear on the right; edit the code and press Check or Run. The full editor, with more examples, is the editor.

Verdicts, not booleans

Section titled “Verdicts, not booleans”

When a checker says “passed”, you should know what it checked. Every Cella check ends in one of three verdicts.

Accept

Checked by two independent kernels, with the assumptions it rests on listed: a postulate, a rewrite rule, termination as judged by the elaborator.

Reject

Wrong, and it says where and which rule was broken.

Unknown

Not known yet, and it says why: a hole, an out-of-budget step count, a definition it depends on that is itself unknown. Unknown spreads: what depends on it is not Accept either.

Two independent kernels: one bug can’t fool both

Section titled “Two independent kernels: one bug can’t fool both”

The kernel the elaborator uses is built for speed. A second checker, written from scratch without sharing code with the first, follows the typing rules one by one and rechecks every definition. If the two disagree, the check fails loudly. Every typing rule has examples that must be accepted and examples that must be rejected.

One syntax, several type theories, chosen by mode

Section titled “One syntax, several type theories, chosen by mode”

Cubical type theory

CCHM: paths, transport, Glue, higher inductive types. Univalence computes.

Quantities and modalities

QTT grades (erased, linear, unrestricted) and multimodal type theory, checked by both kernels.

Proof irrelevance and rewrite rules

Definitional proof irrelevance (SProp) without K, and user-declared rewrite rules whose critical pairs are checked.

Modes

Each definition says which mode it lives in, so it pays only for what it uses, and “this proof does not use univalence” is something you can check.

Programming languages, written in Cella

Section titled “Programming languages, written in Cella”

C11, C++17, C++ on Arduino and ESP32 boards, and Python are deep embeddings: a program is a value, with a type checker and a small-step semantics written in Cella, so whether a C++ program has undefined behavior is a proposition you can prove. The models are tested against the real tools: clang with its sanitizers, avr-gcc and the simavr simulator, CPython. Every kind of undefined behavior the model can report has a minimal pair of programs, measured on those tools, that pins its boundary.

Runs in your browser

Section titled “Runs in your browser”

The checker compiles to WebAssembly. Programs compile to WasmGC and run natively in the browser, in Node and on an ESP32. Use it from JavaScript through the npm packages cella-lang and @cella-lang/*.
