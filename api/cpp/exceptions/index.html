exceptions

cpp.Exceptions.typeName

Section titled “cpp.Exceptions.typeName”

A type’s name as a handler names it (and as an uncaught exception is reported).

cpp.Exceptions.typed

Section titled “cpp.Exceptions.typed”

A statement of exceptions without operands.

cpp.CatchLabel.of

Section titled “cpp.CatchLabel.of”

A handler’s entry: what it catches and its label.

cpp.Exceptions.basesWithin

Section titled “cpp.Exceptions.basesWithin”

A class’s bases, and theirs (fuel bounds the depth).

cpp.TypedExpr.memberPath

Section titled “cpp.TypedExpr.memberPath”

The members’ positions an lvalue reaches from its variable (a base subobject’s path).

cpp.Exceptions.catchable

Section titled “cpp.Exceptions.catchable”

The names an exception of a type can be caught by: its own (the object itself), then, for a class, each of its bases’ that is one subobject reached through public bases (the base subobject, [except.handle]p3), and for a pointer to a class, each pointer to such a base (the path to the subobject it points to).

cpp.Exceptions.classOf

Section titled “cpp.Exceptions.classOf”

The class with constructors a type is, if any.

cpp.Exceptions.throwing

Section titled “cpp.Exceptions.throwing”

throw e: the exception object initialized from e, with the names a handler catches it by. One of a class with constructors is declared and constructed from e (copied, or the temporary itself, [except.throw]p3), then handed to the exception; any other holds e’s value.

cpp.Exceptions.catches

Section titled “cpp.Exceptions.catches”

The name a handler’s written type catches by (a reference catches what it refers to), none for catch (...).

cpp.Declared

Section titled “cpp.Declared”

Statements that declare, and the environment with what they declare.

cpp.Exceptions.declaring

Section titled “cpp.Exceptions.declaring”

A handler’s x declared from the exception (a pointer to the subobject it is caught as): bound to it by reference, else a copy, by the copy constructor for a class with constructors (through a reference to the exception).

cpp.Exceptions.handler

Section titled “cpp.Exceptions.handler”

A handler’s code: the exception adopted into its scope, x declared from it, the body, the handler finished.

cpp.Exceptions.tryStatement

Section titled “cpp.Exceptions.tryStatement”

try { body } catch …: a block with the body run under the handlers’ frame, then a jump past the handlers, each handler at its label (followed by the jump), and the end label.

cpp.Exceptions.statement

Section titled “cpp.Exceptions.statement”

C++‘s statements of exceptions: throw, throw;, try, a function try block (a function’s body in a try; a constructor’s is lowered with its members’ initializations, cpp.classes).

cpp.Exceptions.with

Section titled “cpp.Exceptions.with”

A state with C++’s part changed.

cpp.Exceptions.forget

Section titled “cpp.Exceptions.forget”

Scopes without a block (an exception thrown again leaves the handler’s scope that adopted it).

cpp.CatchLabel.handles

Section titled “cpp.CatchLabel.handles”

Whether a handler catches an exception, with the path to the subobject it refers to: catch (...) (the object itself), or one of the exception’s names.

cpp.CatchLabel.first

Section titled “cpp.CatchLabel.first”

The first handler that catches an exception, and the path to the subobject it refers to.

cpp.Ahead

Section titled “cpp.Ahead”

What an exception meets first on its way out: a handler that catches it, a noexcept function’s body (at a position in the frames), or nothing (it leaves main).

cpp.Exceptions.ahead

Section titled “cpp.Exceptions.ahead”

What an exception meets first in the frames from position i.

cpp.Exceptions.pastLastCall

Section titled “cpp.Exceptions.pastLastCall”

How many frames, from position i, reach past the last call in them (best so far: none is 0).

cpp.Outcome.state

Section titled “cpp.Outcome.state”

The state a configuration ended in, if it has one.

cpp.Exceptions.terminate

Section titled “cpp.Exceptions.terminate”

A termination after unwinding the actual frames: first a trial unwinding the frames of the other choice, and when its output differs, the divergence noted at the throw.

cpp.Exceptions.propagate

Section titled “cpp.Exceptions.propagate”

An exception on its way out (in the state), thrown as libc++abi does: when a handler catches it, the stack unwinds to it; else the run terminates, having unwound only the calls the noexcept function it meets made, or nothing ([except.terminate]p2 leaves it to the implementation; whether unwinding all of it, to the noexcept function’s body or out of main, would change the output is noted).

cpp.Exceptions.run

Section titled “cpp.Exceptions.run”

Running a statement of exceptions.

cpp.Exceptions.uncaught

Section titled “cpp.Exceptions.uncaught”

How a run ends with an exception main let out: reported as uncaught, by its type.

cpp.Pointer.toSubobject

Section titled “cpp.Pointer.toSubobject”

A pointer to the subobject at a path in what it points to (null stays null).

cpp.Conversion

Section titled “cpp.Conversion”

What catching an exception at a path gives: the state, the block of a converted pointer (if any) and the path in the exception object the handler refers to.

cpp.Exceptions.convert

Section titled “cpp.Exceptions.convert”

An exception caught at a path: an object’s subobject (the path, for a handler’s pointer to it); a pointer caught as a pointer to a base, the pointer converted in a block of its own (and no path in it).

cpp.Exceptions.frame

Section titled “cpp.Exceptions.frame”

How leaving passes C++’s frames: at a try block’s, an exception a handler catches becomes the one being handled, and the run jumps to that handler; at a terminating one, an exception ends the run; anything else passes.

cpp.Exceptions.caught

Section titled “cpp.Exceptions.caught”

The pointer to the exception being handled.

cpp.Exceptions.body

Section titled “cpp.Exceptions.body”

A function’s body as C++ runs it: a noexcept function’s under a frame an exception leaving it ends the run at ([except.spec]p5).
