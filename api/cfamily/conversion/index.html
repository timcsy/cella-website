cfamily.CheckResult

Section titled “cfamily.CheckResult”

The result of checking: a value, a refusal at a node, a construct at a node the model does not provide (named: the program may well be valid, so its verdict is unknown, not reject), or a request of the dialect’s (with the types and written types it carries); checking starts again once the dialect has answered it.

cfamily.rejected

Section titled “cfamily.rejected”

A rejection at the node n with the reason in words (not structured yet).

cfamily.undeclaredName

Section titled “cfamily.undeclaredName”

The name nothing declares, used at the node n as what (variable, function, or name), with the header that declares it when a standard one does (Refusal.undeclared).

cfamily.CheckResult.bind

Section titled “cfamily.CheckResult.bind”

Checking f on the value, if there is one.

cfamily.CheckResult.within

Section titled “cfamily.CheckResult.within”

A conversion’s refusal from r as made for the context it is in (initialization, return; without one an assignment’s), which its words depend on (Refusal.withContext).

cfamily.checkMonad

Section titled “cfamily.checkMonad”

Checking is a monad: x <- e in do is CheckResult.bind.

cfamily.Ty.integer

Section titled “cfamily.Ty.integer”

The integer type of a type, if it is one (const aside).

cfamily.Ty.isScoped

Section titled “cfamily.Ty.isScoped”

Whether the type t is a scoped enumeration (C++’s enum class): it takes part in arithmetic and conversions only as itself ([conv.prom]p4, [conv.integral]p1), converting to an integer by a cast ([expr.static.cast]p9).

cfamily.Ty.integral

Section titled “cfamily.Ty.integral”

The integer type a value of the type t is as a switch’s condition or a cast’s operand: an integer’s, or an enumeration’s (a scoped one’s underlying type, [stmt.switch]p2, [expr.static.cast]p9).

cfamily.Ty.float

Section titled “cfamily.Ty.float”

The floating format of a type, if it is one.

cfamily.Ty.floating

Section titled “cfamily.Ty.floating”

The floating type a type is, if it is one.

cfamily.Ty.isArithmetic

Section titled “cfamily.Ty.isArithmetic”

Whether the type is an arithmetic type (integer or floating).

cfamily.Ty.isPointer

Section titled “cfamily.Ty.isPointer”

Whether the type is a pointer type.

cfamily.Ty.pointee

Section titled “cfamily.Ty.pointee”

The pointed-to type of a pointer type, else the type itself.

cfamily.Ty.voidPointer

Section titled “cfamily.Ty.voidPointer”

The type void *.

cfamily.Ty.isVoidPointer

Section titled “cfamily.Ty.isVoidPointer”

Whether the type is void * (with any qualifiers on the void).

cfamily.Ty.isScalar

Section titled “cfamily.Ty.isScalar”

Whether the type is a scalar type: arithmetic or pointer (C11 6.2.5p21).

cfamily.TypedExpr.isNullConstant

Section titled “cfamily.TypedExpr.isNullConstant”

Whether an expression is a null pointer constant: the integer 0 or a null pointer (C11 6.3.2.3p3).

cfamily.TypedExpr.nullAs

Section titled “cfamily.TypedExpr.nullAs”

A null pointer constant as the null pointer of a pointer type, at its node.

cfamily.TypedExpr.rvalue

Section titled “cfamily.TypedExpr.rvalue”

The value of an lvalue: an array decays to a pointer to its first element (C11 6.3.2.1p3).

cfamily.TypedExpr.toIntegerType

Section titled “cfamily.TypedExpr.toIntegerType”

An integer value converted to an integer type (unchanged if it has the type).

cfamily.TypedExpr.toFloatType

Section titled “cfamily.TypedExpr.toFloatType”

An arithmetic value converted to a floating type (unchanged if it is of the type; a conversion between two floating types of one format keeps the value).

cfamily.Ty.widerFloat

Section titled “cfamily.Ty.widerFloat”

The floating type of the usual arithmetic conversions: the floating operand of the greater rank (C11 6.3.1.8p1, C++ [expr.arith.conv]p1; by the type, not the format: a double and a long double of one format give long double).

cfamily.IntegerType.ofDecimal

Section titled “cfamily.IntegerType.ofDecimal”

The type of a decimal integer constant: the first of int, long, long long that holds it (C11 6.4.4.1p5).

cfamily.IntegerSuffix.of

Section titled “cfamily.IntegerSuffix.of”

The suffixes an integer constant may have (C11 6.4.4.1p1: u, l or ll in either case, in either order; not lL), as whether unsigned and how many l.

cfamily.IntegerType.candidates

Section titled “cfamily.IntegerType.candidates”

The types an integer constant may have, in order (C11 6.4.4.1p5): from int, long or long long by its l’s; only the unsigned ones with u; a constant not in decimal may also be the unsigned type of each rank.

cfamily.IntegerType.ofWritten

Section titled “cfamily.IntegerType.ofWritten”

The type of an integer constant as written: the first candidate that holds its value; none when the suffix is not one or no candidate holds it.

cfamily.BinaryOp.isShift

Section titled “cfamily.BinaryOp.isShift”

Whether a binary operator is a shift.

cfamily.Rules.truthType

Section titled “cfamily.Rules.truthType”

The type of a truth value under the rules on platform p: bool in C++, int in C (Rules.truthIsBool).

cfamily.BinaryOp.isLogical

Section titled “cfamily.BinaryOp.isLogical”

Whether a binary operator is && or ||.

cfamily.BinaryOp.isEquality

Section titled “cfamily.BinaryOp.isEquality”

Whether a binary operator is == or !=.

cfamily.BinaryOp.isRelational

Section titled “cfamily.BinaryOp.isRelational”

Whether a binary operator is <, <=, > or >=.

cfamily.BinaryOp.takesFloat

Section titled “cfamily.BinaryOp.takesFloat”

Whether a binary operator applies to floating operands: + - * / and the comparisons (C11 6.5.5p2, 6.5.7p2).

cfamily.TypedExpr.integerBinaryOf

Section titled “cfamily.TypedExpr.integerBinaryOf”

Two integer operands: arithmetic in the common type, a shift in the promoted left type, a comparison of the operands in the common type giving the truth type.

cfamily.TypedExpr.pointerBinaryOf

Section titled “cfamily.TypedExpr.pointerBinaryOf”

Operands with a pointer (C11 6.5.6, 6.5.8, 6.5.9): pointer plus or minus an integer, the difference of two pointers of one type, comparisons of pointers of one type or with a null pointer constant (of the truth type). op is the operator at node n with operands a and b; ext writes the dialect’s types, p is the platform’s sizes, and wrong makes the refusal from the operands’ types written out.

cfamily.TypedExpr.floatBinaryOf

Section titled “cfamily.TypedExpr.floatBinaryOf”

Floating operands (one at least): converted to the wider type, arithmetic giving it and a comparison the truth type; % shifts and bitwise operators are rejected. op is the operator at node n with operands a and b, tgt the target’s floating formats, and wrong makes the refusal from the operands’ types written out.

cfamily.TypedExpr.scopedBinaryOf

Section titled “cfamily.TypedExpr.scopedBinaryOf”

A binary operator with an operand of a scoped enumeration (C++‘s enum class): only a comparison of two values of the same one, compared as their underlying type ([expr.rel]p6, [expr.eq]p6: the built-in candidates are for the enumeration itself, [over.built]p15); anything else has no operator (clang: invalid operands to binary expression). op is the operator at node n with operands a and b; ext writes the dialect’s types, p is the platform, truth the comparison’s type, and wrong makes the refusal from the operands’ types written out.

cfamily.TypedExpr.binaryOf

Section titled “cfamily.TypedExpr.binaryOf”

A binary operator on two scalar values (struct operands and the dialect’s types are rejected): && and || take any scalars; with a floating operand, floating arithmetic; two integers; else pointers. The comparisons, && and || give the truth type (int in C, bool in C++). op is the operator at node n with operands a0 and b0; ext writes the dialect’s types for the program’s tables g, and tgt is the target.

cfamily.TypedExpr.unaryOf

Section titled “cfamily.TypedExpr.unaryOf”

A unary operator: ! on a scalar gives the truth type (int in C, bool in C++); - on a floating value stays floating;

  • is the value itself (C11 6.5.3.3p2), of a pointer too where the dialect allows it; else the promoted integer.

cfamily.ConversionExtension

Section titled “cfamily.ConversionExtension”

How a dialect converts to and from its own types as if by assignment, or none for the core’s rules (C++: a C string to std::string, an object of a derived class to its base, a value bound to a reference): the converted expression with the statements it needs first (a temporary a const reference binds to).

cfamily.ConversionExtension.empty

Section titled “cfamily.ConversionExtension.empty”

The conversion extension of a dialect without types of its own.

cfamily.TypedExpr.conditionalType

Section titled “cfamily.TypedExpr.conditionalType”

The type of c ? a : b from the operands’ values (C11 6.5.15p3-6): arithmetic operands give their common type, or their own type when they have the same one and keepsSame (the dialect’s rule, C++ [expr.cond]p7); pointers of one type, a pointer and a null pointer constant, void * and an object pointer; one struct type.

cfamily.TypedExpr.castTo

Section titled “cfamily.TypedExpr.castTo”

A cast (C11 6.5.4): to an arithmetic type from an arithmetic value (or a pointer to _Bool); to a pointer from a null pointer constant, a pointer of that type, or a pointer to a character type when it is to one too (the same object’s bytes, C11 6.3.2.3p7); casts to arrays and structs are not allowed.

cfamily.Ty.noArithmeticConversion

Section titled “cfamily.Ty.noArithmeticConversion”

Why a value of the non-arithmetic type source does not convert to an arithmetic one (target is “Integer” or “Floating”), as Refusal.noConversion’s what and name: from a pointer, from a class or other named type (by its name), or from another type.

cfamily.TypedExpr.assignArithmetic

Section titled “cfamily.TypedExpr.assignArithmetic”

The conversion as if by assignment to an arithmetic type (C11 6.5.16.1): from an arithmetic value, or a pointer to _Bool (6.3.1.2); a value that does not convert is refused as wrong makes it from its what and name. a is the value at node n converted to t, with the platform p’s sizes.

cfamily.TypedExpr.assignTo

Section titled “cfamily.TypedExpr.assignTo”

The core’s conversion as if by assignment (C11 6.5.16.1): arithmetic, pointers, and structs and unions of the same type copied whole; arrays and functions cannot be assigned (a dialect’s own conversions come first, CheckDialect.assignLifted). A value that does not convert is refused with its type and the target’s, written as the dialect’s types write them for the program’s tables g. a is the value at node n converted to t, under the dialect’s rules and the platform p.
