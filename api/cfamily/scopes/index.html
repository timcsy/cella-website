scopes

cfamily.ScopedName

Section titled “cfamily.ScopedName”

A name a declaration puts in a scope: the node it is reported at, the declaration’s label (what a use of the name refers to) and the name.

cfamily.Scopes.named

Section titled “cfamily.Scopes.named”

The name name declared by the declaration labelled x at n, none when it is unnamed.

cfamily.Scopes.bound

Section titled “cfamily.Scopes.bound”

The names a structured binding declares, at its node n.

cfamily.Scopes.declares

Section titled “cfamily.Scopes.declares”

The names the statement s declares in the block it is directly in.

cfamily.Scopes.parameters

Section titled “cfamily.Scopes.parameters”

The names of the parameters ps, at the node n of what declares them.

cfamily.Scopes.twice

Section titled “cfamily.Scopes.twice”

The first name declared twice among the names ds in one scope, after the names seen before them: the later declaration.

cfamily.Scopes.inBlock

Section titled “cfamily.Scopes.inBlock”

The first name declared twice in a block of statements ss, with the names outer already in its scope.

cfamily.Scopes.outermost

Section titled “cfamily.Scopes.outermost”

The first name declared twice in the outermost block of the statement s, with the names outer already in its scope (none when it is not a block).

cfamily.Scopes.clauseStatements

Section titled “cfamily.Scopes.clauseStatements”

The statements of a switch’s clauses cls: one block.

cfamily.Scopes.inStatement

Section titled “cfamily.Scopes.inStatement”

The first name declared twice in a scope inside a statement (forInBody: a for’s init-statement is in its body’s outermost block).

cfamily.Scopes.inStatements

Section titled “cfamily.Scopes.inStatements”

The first name declared twice in a scope inside the statements ss (forInBody as for Scopes.inStatement).

cfamily.Scopes.inClauses

Section titled “cfamily.Scopes.inClauses”

The first name declared twice in a scope inside a switch’s clauses cls (their statements’ own blocks; forInBody as for Scopes.inStatement).

cfamily.Scopes.inHandlers

Section titled “cfamily.Scopes.inHandlers”

The first name declared twice in the handlers hs: each one’s name is in its body’s outermost block (forInBody as for Scopes.inStatement).

cfamily.Scopes.inFunctionBody

Section titled “cfamily.Scopes.inFunctionBody”

The first name declared twice in a function with parameters ps declared at n and its body: the parameters are in the body‘s outermost block, and in a function-try-block’s handlers’ too (forInBody as for Scopes.inStatement).

cfamily.Scopes.inFunction

Section titled “cfamily.Scopes.inFunction”

The first name declared twice in the function f (forInBody as for Scopes.inStatement).

cfamily.Scopes.inMembers

Section titled “cfamily.Scopes.inMembers”

The first name declared twice in a class’s members ms: its member functions, constructors and destructor (and its nested classes’; forInBody as for Scopes.inStatement).

cfamily.Scopes.inClass

Section titled “cfamily.Scopes.inClass”

The first name declared twice in the class d (forInBody as for Scopes.inStatement).

cfamily.Scopes.inItems

Section titled “cfamily.Scopes.inItems”

The first name declared twice in a block scope of the items: functions, function templates, classes and class templates, at the outermost level and in namespaces (forInBody as for Scopes.inStatement).

cfamily.Scopes.firstRedeclared

Section titled “cfamily.Scopes.firstRedeclared”

The first name a program’s items declare twice in one block scope, as the rules say a for’s scope is.

cfamily.Referent

Section titled “cfamily.Referent”

What a name in scope refers to: a declaration, by its label; a data member of the class whose member function the name is in (an implicit this->, C++ [class.mfct.non.static]p2); or a static member function of a class, by its full name through the namespaces and classes around it (ns::D::f, Outer::Inner::f: the function a C++ checker lowers it to, [class.static.mfct]).

cfamily.NameScope

Section titled “cfamily.NameScope”

The names in scope, the innermost first, each with what it refers to.

cfamily.NameScope.with

Section titled “cfamily.NameScope.with”

The scope with the declarations ds added (inside the ones it has).

cfamily.NameScope.lookup

Section titled “cfamily.NameScope.lookup”

What name refers to in the scope: the innermost declaration of it.

cfamily.Scopes.enumerators

Section titled “cfamily.Scopes.enumerators”

The names the enumerators cs declare (an enumeration constant is named by its declaration’s label).

cfamily.Scopes.visibleAfter

Section titled “cfamily.Scopes.visibleAfter”

The names the statement s puts in the scope of the statements after it in its block: what it declares, and the constants of an enumeration it defines.

cfamily.Resolving

Section titled “cfamily.Resolving”

What resolving a program’s names needs besides the scopes: whether it is C++, the names of the functions it defines (a name no scope declares that names one is that function, as a value), its classes (for the members of base classes), the namespaces the items being resolved are in, each followed by :: (a::b::; empty at file scope: a class’s static member functions are named through them), whether they are a class template’s (its static member functions are its instances’, not functions of their own), and the marks of the members defined outside their classes: each one’s label and the scope around its definition (iMemberAt).

cfamily.Resolving.stream

Section titled “cfamily.Resolving.stream”

A standard stream written by its name in C++, with or without std:: (std::cin, cout): the stream at n.

cfamily.Resolving.unbound

Section titled “cfamily.Resolving.unbound”

A name at n that no scope declares: a function the program defines, as a value; else a name the program’s environment may declare (a header’s constant, a board’s object, C++’s standard streams as operands), which the checker looks up and otherwise rejects as undeclared at n. r is what resolving needs besides the scopes.

cfamily.Resolving.streamObject

Section titled “cfamily.Resolving.streamObject”

An expression e with, in C++, the object of a member function’s call that names a standard stream (cin.ignore(), cout.flush()) as the console’s stream (eStdin, eStdout, eStderr), as a front end that resolves its names writes it; a stream elsewhere stays the name (eConst "cout": ostream_iterator<int>(cout, " "), an argument bound to std::ostream &), since the console’s stream as an operand is C’s FILE * (fgets(line, n, stdin)). r is what resolving needs besides the scopes.

cfamily.Scopes.name

Section titled “cfamily.Scopes.name”

A name written in an expression e, resolved in the scope (other expressions as they are, but a C++ standard stream as a member call’s object, Resolving.streamObject). r is what resolving needs besides the scopes.

cfamily.Scopes.mapIn

Section titled “cfamily.Scopes.mapIn”

Resolving the names in expressions in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.expression

Section titled “cfamily.Scopes.expression”

An expression e with its names resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.expressions

Section titled “cfamily.Scopes.expressions”

Expressions es with their names resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.expressionOption

Section titled “cfamily.Scopes.expressionOption”

An optional expression e with its names resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.type

Section titled “cfamily.Scopes.type”

A written type t with the names in it resolved in the scope (an array’s length written as an expression). r is what resolving needs besides the scopes.

cfamily.Scopes.fields

Section titled “cfamily.Scopes.fields”

Members of a struct or union fs with the names in their types resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.structDefinition

Section titled “cfamily.Scopes.structDefinition”

A struct or union’s definition d with the names in its members’ types resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.parametersIn

Section titled “cfamily.Scopes.parametersIn”

Parameters ps with the names in their default arguments resolved in the scope (outside the function: a default argument may not use the parameters, C++ [dcl.fct.default]p9), and those in their types in the scope with the parameters before each (void f(int n, int a[n]), C11 6.2.1p4: a parameter’s scope starts at its declarator). r is what resolving needs besides the scopes.

cfamily.Scopes.enumeratorsIn

Section titled “cfamily.Scopes.enumeratorsIn”

Enumerators cs with the names in their values resolved: each value sees the scope and the enumerators before it. r is what resolving needs besides the scopes.

cfamily.Scopes.statement

Section titled “cfamily.Scopes.statement”

A statement s with its names resolved in the scope. A declaration’s name is in scope in its own initializer (C11 6.2.1p7, C++ [basic.scope.pdecl]p1); a for’s declaration in its condition, step and body; a range for’s in its body (the range is outside); a handler’s in its body; a lambda’s parameters in its body. r is what resolving needs besides the scopes.

cfamily.Scopes.statements

Section titled “cfamily.Scopes.statements”

Statements ss of one block with their names resolved: each sees the scope and what the ones before it declare. r is what resolving needs besides the scopes.

cfamily.Scopes.clauses

Section titled “cfamily.Scopes.clauses”

A switch’s clauses cls with their names resolved: their statements are one block. In the scope; r is what resolving needs besides the scopes.

cfamily.Scopes.handlers

Section titled “cfamily.Scopes.handlers”

Handlers hs with their names resolved: each one’s exception-declaration is in its body. In the scope; r is what resolving needs besides the scopes.

cfamily.Scopes.function

Section titled “cfamily.Scopes.function”

A function f with its names resolved in the scope: its parameters are in its body. r is what resolving needs besides the scopes.

cfamily.Resolving.inNamespace

Section titled “cfamily.Resolving.inNamespace”

What resolving needs (r, outside it) inside the namespace name of the items being resolved.

cfamily.Resolving.fullName

Section titled “cfamily.Resolving.fullName”

A class’s full name, from its name as written or declared: as it is when qualified (a base ns::Base), else through the namespaces the items are in (Resolving.within). r is what resolving needs besides the scopes.

cfamily.Scopes.within

Section titled “cfamily.Scopes.within”

before::name, or name when before is empty.

cfamily.Scopes.memberNames

Section titled “cfamily.Scopes.memberNames”

The names the members ms of the class whose full name is full put in its scope: a data member as itself (through this), a static data member and an enumerator of the class by their declarations, a static member function as the function full::f (not in a class template’s, Resolving.inTemplate). r is what resolving needs besides the scopes.

cfamily.Resolving.classNamed

Section titled “cfamily.Resolving.classNamed”

The class named name among the program’s classes. r is what resolving needs besides the scopes.

cfamily.Scopes.classNames

Section titled “cfamily.Scopes.classNames”

The names of the members of the class d (whose full name is full) and then of its bases’ (a member of the class hides one of a base, C++ [class.member.lookup]); a base the program does not define (a template’s dependent one) adds none ([temp.dep]p3). fuel bounds the depth of bases. r is what resolving needs besides the scopes.

cfamily.Resolving.depth

Section titled “cfamily.Resolving.depth”

How deep bases may go (Scopes.classNames): one more than the program’s classes (r’s).

cfamily.Scopes.qualifiedBy

Section titled “cfamily.Scopes.qualifiedBy”

A class’s names names (Scopes.classNames) written through it as written: written::n ([class.qual]p1, a static member, an enumerator, a member found in a base); outside: as code outside the class’s member functions sees them, where a non-static data member is not one.

cfamily.Scopes.qualifiedNested

Section titled “cfamily.Scopes.qualifiedNested”

The names of the classes nested among the members ms (and in them) written through them after written (Outer::Inner::k after Outer, Inner::k after nothing); full is the full name of the class they are in, outside as for Scopes.qualifiedBy. r is what resolving needs besides the scopes.

cfamily.Scopes.qualifiedMember

Section titled “cfamily.Scopes.qualifiedMember”

The names of the member m, a nested class, and of the classes in it, written through them after written; full, outside and r as for Scopes.qualifiedNested.

cfamily.Scopes.qualifiedNames

Section titled “cfamily.Scopes.qualifiedNames”

The names of the class d (and of the classes nested in it) written through it from outside it, as the items after it see them: C::n, C::f, Outer::Inner::k (C++ [class.qual]p1). r is what resolving needs besides the scopes.

cfamily.Scopes.classScope

Section titled “cfamily.Scopes.classScope”

The scope of the members of the class d, whose full name is full: its names (Scopes.classNames), also written through it (C::n, and C::field for a non-static data member, in a member function the object’s), and its nested classes’ written through them (Inner::k, C::Inner::k), inside the scope around it. r is what resolving needs besides the scopes.

cfamily.Scopes.memberInits

Section titled “cfamily.Scopes.memberInits”

A constructor’s member initializers inits with their names resolved in scope (the class’s, with the constructor’s parameters); r is what resolving needs besides the scopes.

cfamily.Scopes.memberScope

Section titled “cfamily.Scopes.memberScope”

The scope a member labelled x is resolved in: the class’s as wrap makes it from the scope around the member’s definition when r has that marked (the definition outside the class sees what is declared before it, C++ [basic.lookup.unqual]), else scope, the class’s where the class is.

cfamily.Scopes.members

Section titled “cfamily.Scopes.members”

The members ms of the class whose full name is full with their names resolved in the class’s scope scope (wrap makes that scope from another scope around the class: a member defined outside the class, Scopes.memberScope); a constructor’s parameters are in its member initializers and body; a nested class’s members see its own names, then the class’s. r is what resolving needs besides the scopes.

cfamily.Scopes.classDefinition

Section titled “cfamily.Scopes.classDefinition”

A class d with its names resolved: its members’ bodies and initializers see the whole class (C++ [class.mem]p6), then the scope around it. r is what resolving needs besides the scopes.

cfamily.Scopes.lastPart

Section titled “cfamily.Scopes.lastPart”

The part of a qualified name after its last :: (a::b::x is x).

cfamily.Scopes.itemNames

Section titled “cfamily.Scopes.itemNames”

The names the item it declares at file scope (or in the namespace it is in), with what they refer to: a variable, an enumeration’s constants, a class’s members written through it (Scopes.qualifiedNames), and a namespace’s names qualified by it (and also unqualified for an inline namespace, [namespace.def]p7). r is what resolving needs besides the scopes.

cfamily.Scopes.itemNamesIn

Section titled “cfamily.Scopes.itemNamesIn”

The names the items declare, the later ones first (as Scopes.itemNames gives each, with r).

cfamily.Scopes.namespaceNames

Section titled “cfamily.Scopes.namespaceNames”

The names the namespace ns declares, which using namespace ns makes visible unqualified, from the namespaces defined before (each a name and the names it declares).

cfamily.Scopes.namespacesAfter

Section titled “cfamily.Scopes.namespacesAfter”

The namespaces defined so far, with the one the item it defines. r is what resolving needs besides the scopes.

cfamily.Scopes.qualifiers

Section titled “cfamily.Scopes.qualifiers”

The ways the namespaces within (a::b::) are written before a name declared in them, from inside them: a::b:: and b:: (a::b::x and b::x name x there too, C++ [namespace.qual]); none at file scope.

cfamily.Scopes.withQualified

Section titled “cfamily.Scopes.withQualified”

The names names declared in the namespaces within, also as written through them (Scopes.qualifiers).

cfamily.Scopes.scopeAfter

Section titled “cfamily.Scopes.scopeAfter”

The scope of the items after the item it (the namespaces defined before it): the names it declares (in a namespace, also written through it, Scopes.withQualified), the names of a namespace a using namespace names, and the one name a using-declaration names (using ns::x;). r is what resolving needs besides the scopes.

cfamily.Scopes.item

Section titled “cfamily.Scopes.item”

The item it with its names resolved in the scope (a namespace’s items in order, its own names unqualified inside it; namespaces as for Scopes.scopeAfter). r is what resolving needs besides the scopes.

cfamily.Scopes.items

Section titled “cfamily.Scopes.items”

The items in order with their names resolved: each sees the scope and what the ones before it declare (namespaces as for Scopes.scopeAfter). r is what resolving needs besides the scopes.

cfamily.Scopes.functionNamesOf

Section titled “cfamily.Scopes.functionNamesOf”

The names of the functions the item it defines (at file scope, in a namespace, a function template).

cfamily.Scopes.functionNames

Section titled “cfamily.Scopes.functionNames”

The names of the functions the items define.

cfamily.Scopes.nestedClasses

Section titled “cfamily.Scopes.nestedClasses”

The classes the member m of a class defines (a nested class and the ones inside it).

cfamily.Scopes.nestedClassesIn

Section titled “cfamily.Scopes.nestedClassesIn”

The classes the members ms of a class define.

cfamily.Scopes.withNested

Section titled “cfamily.Scopes.withNested”

The class d and the classes its members define.

cfamily.Scopes.classesOf

Section titled “cfamily.Scopes.classesOf”

The classes the item it defines, nested ones too (at file scope, in a namespace, a class template or specialization).

cfamily.Scopes.classesIn

Section titled “cfamily.Scopes.classesIn”

The classes the items define.

cfamily.Scopes.enclosingNames

Section titled “cfamily.Scopes.enclosingNames”

The names of the namespaces around the class cls (written with them, a::b::C), the innermost first (namespaces as for Scopes.scopeAfter): a member’s definition sees them even where it is written outside them.

cfamily.Scopes.markedIn

Section titled “cfamily.Scopes.markedIn”

The label of each member the items mark as defined outside its class (iMemberAt) with the scope around that definition: what is declared before it, and its class’s namespaces. r, namespaces and scope as for Scopes.items.

cfamily.Scopes.isName
