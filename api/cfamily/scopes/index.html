scopes

cfamily.ScopedName

Section titled “cfamily.ScopedName”

A name a declaration puts in a scope: the node it is reported at, the declaration’s label (what a use of the name refers to) and the name.

cfamily.Scopes.named

Section titled “cfamily.Scopes.named”

The name name declared by the declaration labelled x at n, none when it is unnamed.

cfamily.Scopes.bound

Section titled “cfamily.Scopes.bound”

The names a structured binding declares, at its node n.

cfamily.Scopes.declares

Section titled “cfamily.Scopes.declares”

The names the statement s declares in the block it is directly in.

cfamily.Scopes.parameters

Section titled “cfamily.Scopes.parameters”

The names of the parameters ps, at the node n of what declares them.

cfamily.Scopes.twice

Section titled “cfamily.Scopes.twice”

The first name declared twice among the names ds in one scope, after the names seen before them: the later declaration.

cfamily.Scopes.inBlock

Section titled “cfamily.Scopes.inBlock”

The first name declared twice in a block of statements ss, with the names outer already in its scope.

cfamily.Scopes.outermost

Section titled “cfamily.Scopes.outermost”

The first name declared twice in the outermost block of the statement s, with the names outer already in its scope (none when it is not a block).

cfamily.Scopes.clauseStatements

Section titled “cfamily.Scopes.clauseStatements”

The statements of a switch’s clauses cls: one block.

cfamily.Scopes.inFunctionBody

Section titled “cfamily.Scopes.inFunctionBody”

The first name declared twice in a function with parameters ps declared at n and its body: the parameters are in the body‘s outermost block, and in a function-try-block’s handlers’ too (forInBody as for Scopes.inStatement).

cfamily.Scopes.inFunction

Section titled “cfamily.Scopes.inFunction”

The first name declared twice in the function f (forInBody as for Scopes.inStatement).

cfamily.Scopes.inMembers

Section titled “cfamily.Scopes.inMembers”

The first name declared twice in a class’s members ms: its member functions, constructors and destructor (and its nested classes’; forInBody as for Scopes.inStatement).

cfamily.Scopes.inClass

Section titled “cfamily.Scopes.inClass”

The first name declared twice in the class d (forInBody as for Scopes.inStatement).

cfamily.Scopes.inItems

Section titled “cfamily.Scopes.inItems”

The first name declared twice in a block scope of the items: functions, function templates, classes and class templates, at the outermost level and in namespaces (forInBody as for Scopes.inStatement).

cfamily.Scopes.firstRedeclared

Section titled “cfamily.Scopes.firstRedeclared”

The first name a program’s items declare twice in one block scope, as the rules say a for’s scope is.

cfamily.Referent

Section titled “cfamily.Referent”

What a name in scope refers to: a declaration, by its label, or a data member of the class whose member function the name is in (an implicit this->, C++ [class.mfct.non.static]p2).

cfamily.NameScope

Section titled “cfamily.NameScope”

The names in scope, the innermost first, each with what it refers to.

cfamily.NameScope.with

Section titled “cfamily.NameScope.with”

The scope with the declarations ds added (inside the ones it has).

cfamily.NameScope.lookup

Section titled “cfamily.NameScope.lookup”

What name refers to in the scope: the innermost declaration of it.

cfamily.Scopes.enumerators

Section titled “cfamily.Scopes.enumerators”

The names the enumerators cs declare (an enumeration constant is named by its declaration’s label).

cfamily.Scopes.visibleAfter

Section titled “cfamily.Scopes.visibleAfter”

The names the statement s puts in the scope of the statements after it in its block: what it declares, and the constants of an enumeration it defines.

cfamily.Resolving

Section titled “cfamily.Resolving”

What resolving a program’s names needs besides the scopes: whether it is C++, the names of the functions it defines (a name no scope declares that names one is that function, as a value), and its classes (for the members of base classes).

cfamily.Resolving.stream

Section titled “cfamily.Resolving.stream”

A standard stream written by its name in C++, with or without std:: (std::cin, cout): the stream at n.

cfamily.Resolving.unbound

Section titled “cfamily.Resolving.unbound”

A name at n that no scope declares: in C++ a standard stream; a function the program defines, as a value; else a name the program’s environment may declare (a header’s constant, a board’s object), which the checker looks up and otherwise rejects as undeclared at n. r is what resolving needs besides the scopes.

cfamily.Scopes.name

Section titled “cfamily.Scopes.name”

A name written in an expression e, resolved in the scope (other expressions as they are). r is what resolving needs besides the scopes.

cfamily.Scopes.mapIn

Section titled “cfamily.Scopes.mapIn”

Resolving the names in expressions in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.expression

Section titled “cfamily.Scopes.expression”

An expression e with its names resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.expressions

Section titled “cfamily.Scopes.expressions”

Expressions es with their names resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.expressionOption

Section titled “cfamily.Scopes.expressionOption”

An optional expression e with its names resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.type

Section titled “cfamily.Scopes.type”

A written type t with the names in it resolved in the scope (an array’s length written as an expression). r is what resolving needs besides the scopes.

cfamily.Scopes.fields

Section titled “cfamily.Scopes.fields”

Members of a struct or union fs with the names in their types resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.structDefinition

Section titled “cfamily.Scopes.structDefinition”

A struct or union’s definition d with the names in its members’ types resolved in the scope. r is what resolving needs besides the scopes.

cfamily.Scopes.parametersIn

Section titled “cfamily.Scopes.parametersIn”

Parameters ps with the names in their default arguments resolved in the scope (outside the function: a default argument may not use the parameters, C++ [dcl.fct.default]p9), and those in their types in the scope with the parameters before each (void f(int n, int a[n]), C11 6.2.1p4: a parameter’s scope starts at its declarator). r is what resolving needs besides the scopes.

cfamily.Scopes.enumeratorsIn

Section titled “cfamily.Scopes.enumeratorsIn”

Enumerators cs with the names in their values resolved: each value sees the scope and the enumerators before it. r is what resolving needs besides the scopes.

cfamily.Scopes.function

Section titled “cfamily.Scopes.function”

A function f with its names resolved in the scope: its parameters are in its body. r is what resolving needs besides the scopes.

cfamily.Scopes.memberNames

Section titled “cfamily.Scopes.memberNames”

The names the members ms of a class put in its scope: a data member as itself (through this), a static data member and an enumerator of the class by their declarations.

cfamily.Resolving.classNamed

Section titled “cfamily.Resolving.classNamed”

The class named name among the program’s classes. r is what resolving needs besides the scopes.

cfamily.Scopes.classNames

Section titled “cfamily.Scopes.classNames”

The names of the members of the class d and then of its bases’ (a member of the class hides one of a base, C++ [class.member.lookup]); a base the program does not define (a template’s dependent one) adds none ([temp.dep]p3). fuel bounds the depth of bases. r is what resolving needs besides the scopes.

cfamily.Scopes.classScope

Section titled “cfamily.Scopes.classScope”

The scope of the class d’s members: its names (Scopes.classNames) inside the scope around it. r is what resolving needs besides the scopes.

cfamily.Scopes.members

Section titled “cfamily.Scopes.members”

A class’s members ms with their names resolved in the class’s scope; a constructor’s parameters are in its member initializers and body; a nested class’s members see its own names, then the class’s. r is what resolving needs besides the scopes.

cfamily.Scopes.classDefinition

Section titled “cfamily.Scopes.classDefinition”

A class d with its names resolved: its members’ bodies and initializers see the whole class (C++ [class.mem]p6), then the scope around it. r is what resolving needs besides the scopes.

cfamily.Scopes.lastPart

Section titled “cfamily.Scopes.lastPart”

The part of a qualified name after its last :: (a::b::x is x).

cfamily.Scopes.namespaceNames

Section titled “cfamily.Scopes.namespaceNames”

The names the namespace ns declares, which using namespace ns makes visible unqualified, from the namespaces defined before (each a name and the names it declares).

cfamily.Scopes.namespacesAfter

Section titled “cfamily.Scopes.namespacesAfter”

The namespaces defined so far, with the one the item it defines.

cfamily.Scopes.scopeAfter

Section titled “cfamily.Scopes.scopeAfter”

The scope of the items after the item it (the namespaces defined before it): the names it declares, the names of a namespace a using namespace names, and the one name a using-declaration names (using ns::x;).

cfamily.Scopes.withNested

Section titled “cfamily.Scopes.withNested”

The class d and the classes its members define.

cfamily.Scopes.isName

Section titled “cfamily.Scopes.isName”

Whether the expression e is a name to resolve.

cfamily.Scopes.resolved

Section titled “cfamily.Scopes.resolved”

The program’s items with every name written (eName) resolved by the scopes it is in (as the lang says): to the declaration it names (eVar), a data member of the class (eSelf), or what no scope declares (Resolving.unbound). Items without names to resolve are as they are.
