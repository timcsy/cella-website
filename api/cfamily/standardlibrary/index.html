cfamily.Library.mathNames

Section titled “cfamily.Library.inexactMathNames”

The <math.h> functions whose accuracy the C standard leaves to the implementation (C11 5.2.4.2.2p6): the model gives the correctly rounded result, which the verdict assumes of the platform’s math library (libm:math.correctlyRounded; glibc and Apple’s libm are within an ulp but not always correctly rounded). sqrt is exact by IEEE 754, fmod exact.

cfamily.Library.abs

cfamily.Library.checkArray

Section titled “cfamily.Library.checkArray”

qsort’s and bsearch’s array (C11 7.22.5p1): a valid pointer even for 0 elements (not NULL, to a live object); for more, size the element’s and all n elements in the array.

cfamily.Library.sign

Section titled “cfamily.Library.sign”

A comparison’s sign: -1, 0 or 1.

cfamily.Library.checkOrder

Section titled “cfamily.Library.checkOrder”

qsort’s check of two elements of the sorted array, i before j (C11 7.22.5p4): c compares the i-th with the j-th, r the j-th with the i-th, and z says whether every neighbour from the i-th to the j-th compares equal. The results agree with an order the array is sorted by when c is not above 0, r has the opposite sign, and c is 0 exactly when z says so (the equal elements are the runs of equal neighbours).

cfamily.Library.checkSorted

Section titled “cfamily.Library.checkSorted”

bsearch’s check of two neighbouring elements (C11 7.22.5.1p2): a compares the key with the one before, b with the one after; the elements below the key come first, then the equal ones, then the ones above.

cfamily.Library.hold

Section titled “cfamily.Library.hold”

qsort’s and bsearch’s array held while they run (C11 7.22.5p3: the comparator is not to alter it): the elements from the base on, or the whole object a pointer to one points to; a pointer into the bytes of an object is not held (the check misses writes there, it does not reject).

cfamily.Library.release
