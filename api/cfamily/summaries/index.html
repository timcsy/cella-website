Section titled “cfamily.Effects.none”

Nothing.

cfamily.Effects.any

Section titled “cfamily.Effects.any”

Everything (a call through a pointer).

cfamily.Effects.inputOutputOnly

Section titled “cfamily.Effects.inputOutputOnly”

Input or output only.

cfamily.Effects.readingElsewhere

Section titled “cfamily.Effects.readingElsewhere”

Reading memory elsewhere only.

cfamily.Effects.writingElsewhereOnly

Section titled “cfamily.Effects.writingElsewhereOnly”

Writing memory elsewhere only.

cfamily.Effects.writingElsewhere

Section titled “cfamily.Effects.writingElsewhere”

Writing (and reading) memory elsewhere.

cfamily.Effects.mentions

Section titled “cfamily.Effects.mentions”

Whether the name is among the names.

cfamily.Effects.absentFrom

Section titled “cfamily.Effects.absentFrom”

Whether the name is not among the names.

cfamily.Effects.unionIds

Section titled “cfamily.Effects.unionIds”

The names in a and those of b not in a.

cfamily.Effects.join

Section titled “cfamily.Effects.join”

Both effects.

cfamily.Effects.joinAll

Section titled “cfamily.Effects.joinAll”

All the effects.

cfamily.Effects.sameSize

Section titled “cfamily.Effects.sameSize”

Whether two summaries are equal; summaries only grow from round to round, so the sizes of the lists suffice.

cfamily.ChildEffects

Section titled “cfamily.ChildEffects”

A child expression’s effects: evaluating it, and writing it as an lvalue.

cfamily.ChildEffects.evaluatedAll

Section titled “cfamily.ChildEffects.evaluatedAll”

The effects of evaluating the children, joined.

cfamily.ChildEffects.evaluatedOf

Section titled “cfamily.ChildEffects.evaluatedOf”

The effects of evaluating a child.

cfamily.EffectExtension

Section titled “cfamily.EffectExtension”

How a dialect summarizes its own syntax. expression and statement get the effects of the children (expressions in the order they are written; the statements inside); writesReceiver says whether an lvalue is rooted at the object a member function is called on; declaration gives the effects of declaring an object of a written type (its constructors and destructor); library the effects of a library function; indirect whether variables of a written type refer to memory elsewhere (beyond pointers); indirectDeclarations the variables a dialect’s statement declares that refer elsewhere, given those of the statements inside it; keys a function’s name and short name (by which calls name it: C++’s C::f(int) is called as C::f and f); asynchronous whether calling a function lets the environment’s own events happen (simulated time passing: timers, interrupts), which are not the caller’s effects.

cfamily.EffectTable.matching

Section titled “cfamily.EffectTable.matching”

The summaries whose key (name or short name) is f, in reverse after those found so far: a loop over the table (hundreds of functions), not one level of recursion per entry.

cfamily.EffectTable.namedIn

Section titled “cfamily.EffectTable.namedIn”

The joined summaries, among keys and summaries in step, of the functions whose name or short name is f.

cfamily.EffectTable.named

Section titled “cfamily.EffectTable.named”

The joined summaries of the functions whose name or short name is f.

cfamily.EffectTable.throughPointer

Section titled “cfamily.EffectTable.throughPointer”

What a call through a pointer may do: what the functions whose address the program takes may (anything when the table does not know them).

cfamily.EffectTable.defines

Section titled “cfamily.EffectTable.defines”

Whether the program defines a function named f (else it is a library function).

cfamily.Expr.rootVariable

Section titled “cfamily.Expr.rootVariable”

The variable an lvalue is rooted at (a of a[i], s of s.f), if it is one.

cfamily.Expr.throughPointer

Section titled “cfamily.Expr.throughPointer”

Whether an lvalue is reached through a pointer (or a variable that refers elsewhere).

cfamily.Effects.reading

Section titled “cfamily.Effects.reading”

Reading the variable x: a global is recorded, a local is not.

cfamily.Effects.writingAt

Section titled “cfamily.Effects.writingAt”

Writing where an lvalue is: the receiver, memory elsewhere, a global, or a local (nothing).

cfamily.Expr.indexed

Section titled “cfamily.Expr.indexed”

Reading memory elsewhere when indexing through a pointer.

cfamily.Expr.callee

Section titled “cfamily.Expr.callee”

The callee’s effects: its summary if the program defines it, else the library’s.

cfamily.Expr.extension

Section titled “cfamily.Expr.extension”

A dialect’s expression: the dialect’s effects, or (if it does not know it) its children’s.

cfamily.Expr.scanTarget

Section titled “cfamily.Expr.scanTarget”

What scanf writes through a target: the lvalue of &lvalue, else memory elsewhere.

cfamily.Expr.effectsOfSome

Section titled “cfamily.Expr.effectsOfSome”

The effects of an optional expression.

cfamily.Stmt.childOfSome

Section titled “cfamily.Stmt.childOfSome”

An optional expression as a child (none is no children).

cfamily.Stmt.extension

Section titled “cfamily.Stmt.extension”

A dialect’s statement: the dialect’s effects, or (if it does not know it) its children’s.

cfamily.TypeSyntax.indirect

Section titled “cfamily.TypeSyntax.indirect”

Whether variables of a written type refer elsewhere: pointers, arrays as parameters, and the dialect’s.

cfamily.Stmt.indirectExtension

Section titled “cfamily.Stmt.indirectExtension”

A dialect’s statement: what the dialect says it declares, or (if it does not know it) what its statements do.

cfamily.Param.indirect

Section titled “cfamily.Param.indirect”

A parameter’s declaration, if variables of its type refer elsewhere.

cfamily.FunctionDefinition.indirect

Section titled “cfamily.FunctionDefinition.indirect”

The parameters and variables of a function that refer elsewhere.

cfamily.FunctionDefinition.name

Section titled “cfamily.FunctionDefinition.name”

The name of a function.

cfamily.EffectTable.round

Section titled “cfamily.EffectTable.round”

One round: each function’s summary from the table of the previous round.

cfamily.EffectTable.joinedByShortName

Section titled “cfamily.EffectTable.joinedByShortName”

The summaries joined by short name (in step with the keys), one entry per short name.

cfamily.EffectTable.byShort

Section titled “cfamily.EffectTable.byShort”

What a call by a short name alone may do (a member function’s, by its name): the joined summaries of the functions of that short name; none for a name the program does not define.

cfamily.EffectTable.settled

Section titled “cfamily.EffectTable.settled”

Whether two tables have the same summaries.

cfamily.EffectTable.samePair

Section titled “cfamily.EffectTable.samePair”

Whether two entries have the same summary.

cfamily.EffectTable.pairs

Section titled “cfamily.EffectTable.pairs”

The entries of two lists in step.

cfamily.FunctionDefinition.callees

Section titled “cfamily.FunctionDefinition.callees”

The names a function’s body calls by (a call’s name, a member function call’s): its summary can change only when one of theirs did. A call through a pointer calls those the program takes the address of, or anything (*).

cfamily.EffectTable.changedNames

Section titled “cfamily.EffectTable.changedNames”

The names (each function’s name and short name) whose summaries differ between two rounds.

cfamily.EffectTable.affected

Section titled “cfamily.EffectTable.affected”

Whether a function calls a name that changed (or anything, when everything is to be computed).

cfamily.EffectTable.fixpointFrom

Section titled “cfamily.EffectTable.fixpointFrom”

Rounds until no summary changes, at most fuel of them: each round recomputes only the summaries of the functions that call one whose summary changed in the round before (all of them in the first).

cfamily.EffectTable.fixpoint

Section titled “cfamily.EffectTable.fixpoint”

Rounds until no summary changes, at most fuel of them.

cfamily.EffectTable.indirectGlobal

Section titled “cfamily.EffectTable.indirectGlobal”

A global’s declaration, if variables of its type refer elsewhere.

cfamily.EffectTable.pointedAmong

Section titled “cfamily.EffectTable.pointedAmong”

The functions a call through a pointer may call, of the addressed ones (none: may call anything): all of them when the program defines each (by its name or short name).

cfamily.EffectTable.of

Section titled “cfamily.EffectTable.of”

The effect table of a program: its globals (and their written types), its functions (with the bodies of function templates, in a dialect that has them), and the functions whose address it takes (none: unknown); at most one round per function plus one.
