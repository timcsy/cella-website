cfamily.ReasonKind

Section titled “cfamily.ReasonKind”

What a reason means for the verdict: undefined (reject), unspecified (unknown), or a termination the dialect defines (accept, C++’s std::terminate).

cfamily.ReasonDescription

Section titled “cfamily.ReasonDescription”

How a reason is reported: its code, clause, title and kind.

cfamily.ReasonDescription.undefined

Section titled “cfamily.ReasonDescription.undefined”

An undefined behavior’s description.

cfamily.Behavior.describe

Section titled “cfamily.Behavior.describe”

The description of a behavior the standard leaves open; converting an out-of-range floating value is as the rules say (C’s unspecified value, C++’s undefined behavior).

cfamily.Dialect

Section titled “cfamily.Dialect”

A dialect: how it checks, evaluates and runs what the core does not know, how it makes new objects of its own types, how its reasons are reported, and its part of the state at the start.

cfamily.Dialect.check

Section titled “cfamily.Dialect.check”

The checking dialect of expressions.

cfamily.Dialect.runDialect

Section titled “cfamily.Dialect.runDialect”

What running a checked program needs.

cfamily.Dialect.rules

Section titled “cfamily.Dialect.rules”

The dialect’s rules.

cfamily.Dialect.describeStop

Section titled “cfamily.Dialect.describeStop”

How a stop is reported.

cfamily.Problem

Section titled “cfamily.Problem”

A problem in a verdict.

cfamily.Dialect.problem

Section titled “cfamily.Dialect.problem”

The problem a stop or a note is.

cfamily.RunResult

Section titled “cfamily.RunResult”

A verdict: accept, reject, unknown or invalid; the exit code if the program exited; the output; the problems; the implementation’s choices it assumes (made as libc++ makes them, each named once).

cfamily.RunResult.of

Section titled “cfamily.RunResult.of”

A verdict with no exit code and no output.

cfamily.RunResult.exited

Section titled “cfamily.RunResult.exited”

A program that exited: the verdict, the problems, the exit code and the output.

cfamily.Stopped.choice

Section titled “cfamily.Stopped.choice”

The choice a note assumes, if it is one (else the note is a divergence from the standard).

cfamily.Stopped.choices

Section titled “cfamily.Stopped.choices”

The choice a note assumes, as a list (empty for a divergence).

cfamily.Stopped.diverges

Section titled “cfamily.Stopped.diverges”

Whether a note is a divergence from the standard (not an assumed choice).

cfamily.RunResult.once

Section titled “cfamily.RunResult.once”

Names with each kept once, the first time it comes.

cfamily.RunResult.assuming

Section titled “cfamily.RunResult.assuming”

A verdict with the choices its run’s notes (and its stop) assume.

cfamily.RunResult.outOfSteps

Section titled “cfamily.RunResult.outOfSteps”

Running out of steps.

cfamily.RunResult.notChecked

Section titled “cfamily.RunResult.notChecked”

A program that did not check: an empty slot is unknown, anything else rejected.

cfamily.RunResult.notProvided

Section titled “cfamily.RunResult.notProvided”

A program using a construct the model does not provide: unknown, the construct named (the program may be valid).

cfamily.Stopped.placed

Section titled “cfamily.Stopped.placed”

A stop or a note placed in the program: at its node if the program has it, else at the innermost call the program made (a problem in code a dialect generated, such as a library’s, is the call’s).

cfamily.Program.mentions

Section titled “cfamily.Program.mentions”

Whether a node is one of the program’s.

cfamily.NodeId.isLibrary

Section titled “cfamily.NodeId.isLibrary”

Whether a node is a library’s (lib: and its header’s place: code a dialect put in the program for it).

cfamily.Program.wrote

Section titled “cfamily.Program.wrote”

Whether a node is one the program itself wrote (not a library’s put in it).

cfamily.Program.written

Section titled “cfamily.Program.written”

The nodes the program itself wrote (Program.wrote), all of them: what the debugger stops at.

cfamily.Program.madeFrom

Section titled “cfamily.Program.madeFrom”

The written node a dialect’s pass made n from, given n’s parts between colons, last first: the longest part before a colon the program wrote (c8:object, nw:length, C:made:copy), else n.

cfamily.Program.placedNode

Section titled “cfamily.Program.placedNode”

The node a checking problem is reported at: its own if the program wrote it, else the one it was made from by a dialect’s pass (Program.madeFrom), else as it is.

cfamily.Dialect.headerChoices

Section titled “cfamily.Dialect.headerChoices”

The choices a program’s headers assume (a library’s non-standard header, cfamily.rules).

cfamily.RunResult.assumingFirst

Section titled “cfamily.RunResult.assumingFirst”

A verdict with more choices assumed before its own (each once).

cfamily.Dialect.resultOf

Section titled “cfamily.Dialect.resultOf”

The verdict of a run’s outcome: an exit is accept, or unknown after a divergence (the first note); a stop is as its reason’s kind says. The problems are placed in the program (source says which nodes are its).

cfamily.RunDialect.runFor

Section titled “cfamily.RunDialect.runFor”

At most fuel moves, until the run finishes.

cfamily.Dialect.startWith

Section titled “cfamily.Dialect.startWith”

The start of a checked program’s run on an input and the program’s arguments.

cfamily.Dialect.defaultArguments

Section titled “cfamily.Dialect.defaultArguments”

The program’s arguments when none are given: its name only (argc is 1).

cfamily.Dialect.start

Section titled “cfamily.Dialect.start”

The start of a checked program’s run on an input, with the default arguments.

cfamily.Dialect.verdictWithArguments

Section titled “cfamily.Dialect.verdictWithArguments”

Checks a program and runs it on an input and the program’s arguments for at most fuel steps.

cfamily.Dialect.verdictCheckedWithArguments

Section titled “cfamily.Dialect.verdictCheckedWithArguments”

As Dialect.verdictWithArguments, without the choices the headers assume.

cfamily.Outcome.extension

Section titled “cfamily.Outcome.extension”

The dialect’s state at the end of a run (none when it did not finish or the program was not checked).

cfamily.Dialect.verdictAndState

Section titled “cfamily.Dialect.verdictAndState”

Checks a program and runs it on an input for at most fuel steps, with the default arguments: the verdict, and the dialect’s state at the end (what a host shows of the program’s environment).

cfamily.Dialect.verdictAndStateWritten

Section titled “cfamily.Dialect.verdictAndStateWritten”

As Dialect.verdictAndState, the problems placed in what the program wrote (written: a dialect may run more, such as a board’s items and the sketch rewritten for them).

cfamily.Dialect.verdictAndStateChecked

Section titled “cfamily.Dialect.verdictAndStateChecked”

As Dialect.verdictAndStateWritten, without the choices the headers assume.

cfamily.Dialect.verdictOf

Section titled “cfamily.Dialect.verdictOf”

Checks a program and runs it on an input for at most fuel steps, with the default arguments.

cfamily.Problem.json

Section titled “cfamily.Problem.json”

A problem as JSON.

cfamily.RunResult.choiceJson

Section titled “cfamily.RunResult.choiceJson”

An assumed choice as JSON: the implementation it is made as (the part before a colon, else libc++), and its name.

cfamily.RunResult.fields

Section titled “cfamily.RunResult.fields”

A verdict’s JSON fields: verdict, basis, exit, out, problems, and assumes when it assumes an implementation’s choices (a dialect with more to say, a board’s hardware, adds its own after them).

cfamily.RunResult.json

Section titled “cfamily.RunResult.json”

A verdict as JSON: its fields (RunResult.fields).
