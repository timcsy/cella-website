state

cfamily.Stopped

Section titled “cfamily.Stopped”

Why a run stopped, and where: the node, and for a note the calls the run was in (the innermost call’s node first), so a problem in code a dialect generated is reported where the program called it; and the implementation’s choices the stop depends on (a block the library released only because of one).

cfamily.Stopped.of

Section titled “cfamily.Stopped.of”

A stop or a note at a node for a reason.

cfamily.Stopped.at

Section titled “cfamily.Stopped.at”

A stop at a node for a behavior the standard leaves open.

cfamily.Scope

Section titled “cfamily.Scope”

A scope: each declaration in it and its block.

cfamily.Stream

Section titled “cfamily.Stream”

A file the program opened: its name, whether it is read (else written, at the end), how many bytes have been read, whether reading reached the end, and whether it is still open.

cfamily.Chosen

Section titled “cfamily.Chosen”

A block whose fate a library left to an implementation’s choice: released (none), or kept and renumbered (its new number), and the choice. A pointer to the old number still reaches the object when it was kept, assuming the choice.

cfamily.Held

Section titled “cfamily.Held”

An array qsort or bsearch is sorting or searching, which the comparator is not to alter (C11 7.22.5p3): the block, the path to the array, and the elements from low up to high; for a pointer to a whole object (not an element), the object itself (range none).

cfamily.State

Section titled “cfamily.State”

What a run changes: the memory, the scopes, the console, the divergences noted, the calls it is in (their nodes, the innermost first), where strtok goes on from (C11 7.24.5.8p3; none before its first call), the files (names to bytes; none at the start) and the streams the program opened (stream 3 on; 0 to 2 are stdin, stdout and stderr), the blocks left to an implementation’s choice, the arrays being sorted or searched (the innermost first), the words of glibc’s random number generator (the 34 most recent; none before the first rand or srand), and the dialect’s part.

cfamily.State.start

Section titled “cfamily.State.start”

The state before a run: no blocks, one (the global) scope, the input on the console.

cfamily.State.findIn

Section titled “cfamily.State.findIn”

The block of a declaration in a scope.

cfamily.State.findAmong

Section titled “cfamily.State.findAmong”

The block of a declaration, innermost scope first.

cfamily.State.find

Section titled “cfamily.State.find”

The block a declaration names now.

cfamily.State.withMemory

Section titled “cfamily.State.withMemory”

The memory replaced.

cfamily.State.withConsole

Section titled “cfamily.State.withConsole”

The console replaced.

cfamily.State.withExtension

Section titled “cfamily.State.withExtension”

The dialect’s state replaced.

cfamily.Stopped.repeats

Section titled “cfamily.Stopped.repeats”

Whether a note says nothing a note already kept does: the same choice assumed (the verdict lists each choice once), or a divergence at the same node (the first is the one reported).

cfamily.State.addNote

Section titled “cfamily.State.addNote”

A note added (the first is the one reported), unless it repeats one kept: a loop that makes the same choice each time would otherwise keep a note for each, and adding at the end of a list that long is quadratic.

cfamily.State.enterScope

Section titled “cfamily.State.enterScope”

A new innermost scope.

cfamily.State.releaseAll

Section titled “cfamily.State.releaseAll”

Every block of a scope released.

cfamily.State.leaveScope

Section titled “cfamily.State.leaveScope”

Leaving the innermost scope: its objects’ lifetimes end (C11 6.2.4p6).

cfamily.State.isolate

Section titled “cfamily.State.isolate”

An object moved out of the innermost scope into a scope of its own (its cleanup runs there: it can be named, and the scope it left does not find it again).

cfamily.State.bind

Section titled “cfamily.State.bind”

The declaration added to the innermost scope.

cfamily.State.declare

Section titled “cfamily.State.declare”

A new block for a declaration in the innermost scope.

cfamily.State.allocate

Section titled “cfamily.State.allocate”

A new block no declaration names (malloc), and its number.

cfamily.State.unbindIn

Section titled “cfamily.State.unbindIn”

The declaration removed from the innermost scope, its block kept (an object handed to the caller).

cfamily.State.unbind

Section titled “cfamily.State.unbind”

The declaration no longer in the innermost scope.

cfamily.State.changeBlock

Section titled “cfamily.State.changeBlock”

The declaration’s block changed, if it names one that is alive.

cfamily.State.assign

Section titled “cfamily.State.assign”

The declaration’s object replaced.

cfamily.State.reallocate

Section titled “cfamily.State.reallocate”

The declaration’s allocation replaced (a slot is constructed, an object handed over).

cfamily.Object.zeroValue

Section titled “cfamily.Object.zeroValue”

The zero of a scalar type: 0, the null pointer, positive zero.

cfamily.Making

Section titled “cfamily.Making”

How new objects are made: the dialect’s objects of its own types, and the place of a whole union kept as bits (none keeps it as a tree of members, cfamily.representation).

cfamily.Object.freshUnion

Section titled “cfamily.Object.freshUnion”

A new union: kept as bits when its type has a shape (zero: every bit 0 and the first member active), else a tree of members.

cfamily.Object.initializedUnion

Section titled “cfamily.Object.initializedUnion”

A union initialized with its members’ objects, the k-th active: kept as bits (the member’s own, the rest indeterminate) when its type has a shape.

cfamily.Ty.isCharacter

Section titled “cfamily.Ty.isCharacter”

Whether a type is a character type (its objects are bytes).

cfamily.Ty.atPath

Section titled “cfamily.Ty.atPath”

The type of the object at a path in an object of a type.

cfamily.Ty.elementOf

Section titled “cfamily.Ty.elementOf”

The element type of an array type (a type that is not one is its own element).

cfamily.Pointer.bytesOf

Section titled “cfamily.Pointer.bytesOf”

A pointer to elements of a type as a pointer to the bytes of the object it ranges over (C11 6.3.2.3p7): the object at its path (its first byte for a whole object, the element’s for one into an array), if the type has the C layout.

cfamily.Pointer.fromBytes

Section titled “cfamily.Pointer.fromBytes”

A pointer to bytes as a pointer to an object of a type at its first byte (the pointer the bytes came from, C11 6.3.2.3p7): the object at its path when it is of the type, an element of the array there; none when the byte is not where one begins.

cfamily.Pointer.asBytes

Section titled “cfamily.Pointer.asBytes”

A pointer into a block as a pointer to the bytes of the object it ranges over, when its elements are not of a character type (their bytes are themselves) and have the C layout.
