board

arduino.LibraryPart

Section titled “arduino.LibraryPart”

A part of a library: its name (one module) and its items.

arduino.HeaderLibrary

Section titled “arduino.HeaderLibrary”

A library a sketch includes by a header’s name: its parts, each after the ones it uses.

arduino.LibraryPart.of

Section titled “arduino.LibraryPart.of”

A part of a name and its items.

arduino.HeaderLibrary.single

Section titled “arduino.HeaderLibrary.single”

A library of one part.

arduino.BoardLibraries

Section titled “arduino.BoardLibraries”

The libraries a sketch may include, by the boards’ processor: the AVR ones’, the ESP ones’ (the ESP32’s and the ESP8266’s), the ESP32’s only (WiFi.h: the ESP8266’s is ESP8266WiFi.h) and the ESP8266’s only (its EEPROM.h is a flash sector, the ESP32’s an NVS blob).

arduino.BoardLibraries.none

Section titled “arduino.BoardLibraries.none”

No library on any board.

arduino.BoardLibraries.onAvr

Section titled “arduino.BoardLibraries.onAvr”

The libraries given on the AVR boards only.

arduino.CoreEntry

Section titled “arduino.CoreEntry”

A core’s entry: the function a run starts at (AVR’s main, ESP32’s app_main, ESP8266’s user_init), its items (the core’s main.cpp), linked from the core’s archive only when the program does not define a function of that name, and what it runs before the sketch’s setup (AVR’s init(); the ESP cores’ startup is not modeled).

arduino.Board

Section titled “arduino.Board”

A board: its name, items, the core’s entry, target and libraries, and the headers of the libraries other boards have and it does not (a sketch that includes one is rejected at the include, as the compiler stops there).

arduino.CoreEntry.avr

Section titled “arduino.CoreEntry.avr”

AVR’s entry: ArduinoCore-avr’s main.cpp (it calls init() before setup).

arduino.CoreEntry.esp32

Section titled “arduino.CoreEntry.esp32”

The ESP32’s entry: arduino-esp32’s app_main (a sketch’s main is just a function).

arduino.CoreEntry.esp8266

Section titled “arduino.CoreEntry.esp8266”

The ESP8266’s entry: esp8266/Arduino’s user_init (a sketch’s main is just a function).

arduino.Board.startedFunction

Section titled “arduino.Board.startedFunction”

A function, with the core’s startup run before its body when it is main.

arduino.Board.started

Section titled “arduino.Board.started”

Items whose main (a test’s own, run on the board’s items without the core’s entry) first runs what the core’s entry runs before the sketch: the board as a sketch’s setup sees it.

arduino.Board.avr

Section titled “arduino.Board.avr”

AVR’s target: 16-bit int, a 32-bit double.

arduino.Board.esp

Section titled “arduino.Board.esp”

The target of the ESP32 and the ESP8266: 32-bit int and long, a 64-bit double.

arduino.Board.itemsFor

Section titled “arduino.Board.itemsFor”

A board’s items: its header, the pins, then its core (with the core’s String, Print and Serial).

arduino.Board.of

Section titled “arduino.Board.of”

A board of a name, its header, core and the core’s entry, its target, and its libraries.

arduino.Board.headers

Section titled “arduino.Board.headers”

The headers a sketch includes, each once, in order.

arduino.LibraryPart.firsts

Section titled “arduino.LibraryPart.firsts”

The parts, each the first time its name comes (a part two headers bring is included once, as a header’s include guard does).

arduino.Board.included

Section titled “arduino.Board.included”

The items of the libraries a sketch includes that the board has: their parts in order, each once.

arduino.Board.avrCore

Section titled “arduino.Board.avrCore”

The AVR core with its String, Print and Serial (Arduino.h includes WString.h: every sketch has String).

arduino.Board.esp32Serial

Section titled “arduino.Board.esp32Serial”

The ESP32 core’s number formatting, String, Print, Serial and IPAddress (arduino-esp32 3.0.7’s; Arduino.h includes IPAddress.h).

arduino.Board.esp32WithTouch

Section titled “arduino.Board.esp32WithTouch”

The ESP32 core with the first touch sensor’s touchRead (the ESP32).

arduino.Board.s3WithTouch

Section titled “arduino.Board.s3WithTouch”

The ESP32 core with the second touch sensor’s touchRead (the ESP32-S3).

arduino.Board.c3Core

Section titled “arduino.Board.c3Core”

The ESP32 core without a touch sensor (the ESP32-C3).

arduino.Board.esp8266Core

Section titled “arduino.Board.esp8266Core”

The ESP8266 core with its number formatting, String, Print and Serial (esp8266/Arduino 3.1.2’s).

arduino.Board.allWith

Section titled “arduino.Board.allWith”

The boards, by the names the earlier model took (arduino is the Uno; the S3 CAM is an S3 to its core), with the libraries given for their processor.

arduino.Board.withElsewhere

Section titled “arduino.Board.withElsewhere”

A board with the headers of the given libraries it does not have.

arduino.Board.missingHeader

Section titled “arduino.Board.missingHeader”

The first include of a library other boards have and this one does not: its node and header.

arduino.Board.namedWith

Section titled “arduino.Board.namedWith”

The board of a name, with the libraries given (arduino gives all of them; a check that includes none gives BoardLibraries.none, and does not load the libraries’ modules).

arduino.Board.number

Section titled “arduino.Board.number”

An integer an expression writes (a literal, or a literal converted).

arduino.Board.constant

Section titled “arduino.Board.constant”

The integer a global of the items is initialized with (a board’s constant: A0 is 14 on an Uno).

arduino.Board.pinText

Section titled “arduino.Board.pinText”

A pin as the host writes it (a number, or a board’s constant) as a number.

arduino.Board.deviceKey

Section titled “arduino.Board.deviceKey”

A device’s input as the host writes it (dht:room.temperature, the device by its variable’s name) as the headers read it: dht.temperature:@ and the declaration (the primitive finds the device’s number by the declaration it was shown named for); none when the argument has no field. A name no declaration has is kept as written (no device takes it).

arduino.Board.key

Section titled “arduino.Board.key”

An input key as the host writes it (analog:A0, echo:7, dht:room.temperature) as the headers read it: the pin by number, echo as pulse, a device’s by its declaration (Board.deviceKey). A key without its argument (wifi, wifi:) is the first one’s (wifi:0).

arduino.Board.value

Section titled “arduino.Board.value”

An input’s value: an integer, or a number with a fraction or an exponent (a sensor’s temperature) as the board’s double.

arduino.Board.input

Section titled “arduino.Board.input”

One of the host’s inputs, {t, key, value} (milliseconds; an integer, or a number with a fraction), as the environment takes it; names are the program’s declarations (a device’s input names its variable).

arduino.Board.inputOf

Section titled “arduino.Board.inputOf”

An input at a time in milliseconds, as the environment’s (microseconds).

arduino.Board.objectCall

Section titled “arduino.Board.objectCall”

A call the earlier model wrote by an object’s name (Serial.begin): the member function called on the library’s object of that name.

arduino.Macro

Section titled “arduino.Macro”

A function-like macro of a core (constrain(amt, low, high)): its name, its parameters, and the expression it stands for written with them.

arduino.Board.macroPrefix

Section titled “arduino.Board.macroPrefix”

The name a core gives the template that shows clang a macro’s expansion (__cella_macro_constrain).

arduino.Board.returned

Section titled “arduino.Board.returned”

The expression a function’s body returns, when the body is that one return.

arduino.Board.macroOf

Section titled “arduino.Board.macroOf”

The macro a core’s item stands for: a template __cella_macro_<name> whose body returns the expansion.

arduino.Board.macros

Section titled “arduino.Board.macros”

The macros a board’s items define.

arduino.Macro.substituted

Section titled “arduino.Macro.substituted”

A macro’s expansion for arguments: each mention of a parameter replaced by its argument, as the preprocessor does (an argument mentioned twice is evaluated twice).

arduino.Macro.takes

Section titled “arduino.Macro.takes”

Whether a macro is the one a call of a name with a number of arguments calls.

arduino.Board.expandedCall

Section titled “arduino.Board.expandedCall”

A call of a macro (by its name, with as many arguments as it has parameters) expanded in place, its nodes renamed after the call’s (n#0, n#1…): the copies of an argument must not share nodes. Any other expression is kept.

arduino.Board.expanded

Section titled “arduino.Board.expanded”

A program’s items as they run on a board: the calls the earlier model wrote by an object’s name as member calls, and the core’s macros expanded (inner calls first: the rewriting is bottom-up).

arduino.Board.inputs

Section titled “arduino.Board.inputs”

The host’s inputs on a board, a JSON array.

arduino.Board.defines

Section titled “arduino.Board.defines”

Whether items define a function of a name.

arduino.Board.describe

Section titled “arduino.Board.describe”

Why a run on a board stops, as the Arduino core says it: a pin the board does not have (__cella_pin_on_board’s precondition) is undefined behavior of the core’s pin functions; anything else as C++ says.

arduino.Board.dialect

Section titled “arduino.Board.dialect”

C++ on a board’s target with the host’s inputs, its run starting at the core’s entry, its reasons as the Arduino core says them.

arduino.Board.query

Section titled “arduino.Board.query”

C++’s type query on a board: its target, its checking starting at the core’s entry.

arduino.Board.program

Section titled “arduino.Board.program”

The program run for a program’s items on a board: the board’s items, the libraries it includes, the program’s (expanded), the core’s entry (its main.cpp, linked from the core’s archive only when the program does not define a function of the entry’s name: an AVR sketch’s own main replaces the core’s, which calls init()).

arduino.Board.shown

Section titled “arduino.Board.shown”

What the host was last shown for a key (mode:13).

arduino.Board.pinOf

Section titled “arduino.Board.pinOf”

The pin a key shows a pin’s state for (mode:13, level:13, pwm:13, tone:13).

arduino.Board.pins

Section titled “arduino.Board.pins”

The pins the host was shown, in the order each was first shown.

arduino.Board.modeJson

Section titled “arduino.Board.modeJson”

A pin’s mode by name (as pinMode writes it), null before one was set.

arduino.Board.modeName

Section titled “arduino.Board.modeName”

A mode’s code (1 INPUT, 2 OUTPUT, 3 INPUT_PULLUP) by name; null for no mode.

arduino.Board.present

Section titled “arduino.Board.present”

A value the host was shown, null when it is not there or below the least (pwm -1 is no PWM; tone 0 is no sound).

arduino.Board.pinJson

Section titled “arduino.Board.pinJson”

A pin’s state as the wiring panel reads it: {pin, mode, level, pwm, toneHz}.

arduino.Board.text

Section titled “arduino.Board.text”

A text the host was shown for a key (“” when there is none).

arduino.Board.devices

Section titled “arduino.Board.devices”

The devices of a kind the host was shown names for (lcd:2), in the order each was attached.

arduino.Board.stateKey

Section titled “arduino.Board.stateKey”

The key of a device’s state (lcd.rows:2 for the second device’s rows), from its kind and its own key (lcd:2).

arduino.Board.deviceName

Section titled “arduino.Board.deviceName”

The source name of a device’s declaration, with the elements of an array it is (arm[1]; “” for one allocated).

arduino.Board.displayJson

Section titled “arduino.Board.displayJson”

An LCD as the host reads it, from what its chip showed for its number: {name, lines}, the name its declaration has in the sketch (“” for one allocated) and each row of the module.

arduino.Board.servoJson

Section titled “arduino.Board.servoJson”

A servo as the host reads it: {name, pin, angle}, the angle of the last pulse its motor measured (null before any).

arduino.Board.hardware

Section titled “arduino.Board.hardware”

The hardware at the end, as the earlier model’s showEnv: the clock, the loops, the pins, the servos, the LCDs (named by the sketch’s declarations), the EEPROM’s cells written ([address, byte], in the order first written).

arduino.Board.changeJson

Section titled “arduino.Board.changeJson”

A change of a pin’s value as the host reads it: {t, pin, value}, the time in milliseconds.

arduino.Board.verdict

Section titled “arduino.Board.verdict”

A run on a board as the host reads it: the C++ branch’s verdict, the pins’ changes and the hardware at the end (only the verdict when the run did not start: a program rejected while checking).
