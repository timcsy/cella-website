Cella 語言參考

這份文件說明 Cella 的每一種寫法：怎麼寫、是什麼意思。可以在 cella-lang.org 直接試。

文中每個 cella 程式區塊都是一個完整、可以檢查的檔案。第 1 節一頁看完常用的寫法，後面各節是細節。

1. 一頁看完

Section titled “1. 一頁看完”

幾個最容易寫錯的地方：

別的語言的習慣 Cella 的寫法
a && b、a || b、!a a and b、a or b、not a
f x y、f(x)(y) f(x, y)（呼叫一律圓括號）
List<Int> List(Int)
fn def
class、impl Shape for Circle interface Shape { … }、implement Shape(Circle) { … }
{ ...p, x: 1 } p.with(x = 1)
Point { x: 0 } Point(x = 0)
|x| x + 1、fun x -> x + 1、x -> x + 1 x => x + 1
import a.{b, c} from a import b, c
"hello {name}"（想要插值） f"hello {name}"（普通字串的大括號照字面）
<T>、[T]、{T} 上方寫 @given(T)
-- 註解、/* 註解 */ // 註解（沒有區塊註解）
x? let x = try e（見 11）
@external("js", "f") extern def（這一版照名字對應實作，見 9.2）

寫了這些別的語言的寫法時，錯誤訊息會直接說要改成什麼。

2. 檔案與模組

Section titled “2. 檔案與模組”

一個檔案是一個模組。順序是：mode（選寫，見 10.3）、import、宣告。

  • import m：用模組 m 的公開定義，寫的時候不用前綴。
  • from m import a, b：只取 a、b。
  • export * from m：import 這個檔的檔案也看得到 m 的名字。
  • 模組名可以帶點，點就是目錄：import util.math 是入口旁的 util/math.cella；import cpp.int 是套件 cpp 的子模組。
  • 常用的模組：std（自然數、布林、串列、選項等基礎）、ordering.relations（==、< 等比較要用的介面；這一版要自己 import，少了的時候訊息會說要 import 什麼）、string（f 字串要用的 ToString）、io（輸入輸出）、int（整數）、fin（有限的索引）。
  • 函式庫（標準庫與套件）定義的名字由它自己決定，不看在哪個檔：def cpp.add(…) 叫 cpp.add。程式的定義帶模組名（util.math.m）。
  • 預設公開；只給這個模組用的定義標 private（見 3.5）。

不用 namespace 區塊：名字直接帶前綴（def IntegerType.divide(…)）。

3. 定義

Section titled “3. 定義”

3.1 def

Section titled “3.1 def”
  • def 名字(參數) -> 型別 { 本體 }。沒有參數的值寫 def 名字: 型別 = 值；要算的值寫 def 名字() -> 型別 { … }，呼叫時寫 名字()。
  • 回傳型別一定要寫（-> T）。
  • 本體的最後一行是結果；前面的行用 let 取名字。

3.2 參數與型別參數

Section titled “3.2 參數與型別參數”
  • 參數寫 名字: 型別，用逗號隔開（換行時也加逗號）。
  • @given(…) 寫在定義的上方：
    • @given(A)：型別參數，呼叫時由 Cella 推出；@given(A, B) 多個。
    • @given(n: Nat)：Cella 推出來的值。
    • @given(Monoid(A))、@given(d: Monoid(A))：介面的實作（見 4.5）；要在本體裡點名時給名字。
    • @given(u: Level) 加 Type(u)：宇宙層級。
  • 型別參數與 @given 的名字沒有宣告就用，是錯誤。
  • @given 不寫在參數清單裡：一律在上方。Cella 把每個隱式參數放在它用到的最後一個明確參數之後。
  • 推不出來或要指定時，在呼叫裡用名字給，寫在明確引數之後、順序不拘：twice(f, 3, A = Nat)。只有具名引數的呼叫（Point(x = 0)）是建 record。

很多定義用同一組前提時，寫一個 given { … } 區塊：

  • given { … } 裡一行一個前提，不加逗號：A、n: Nat、A: Type(u)，或沒有名字的介面條件 Combine(A)。從區塊寫的地方到檔案結尾，每個定義都可以用。
  • 每個定義只拿它的型別用到的前提（參數的型別、回傳型別、自己的 @given、@shows；type、record、interface 是整個宣告），加上這些前提的型別再用到的（A: Type(u) 帶來 u）。沒有名字的介面條件在它談到的前提都拿了時一起拿；有名字的照名字。上面的 twice 和 keep 等於寫了 @given(A, Combine(A))，size 什麼都沒拿。
  • 前提只在本體或證明裡用到、型別沒用到，是錯誤：寫進型別，或在那個定義上寫 @given。改證明不會改到證明的命題。
  • 定義自己的 @given 接在拿到的前提之後。同一個名字只有一個意思：多個區塊累加，但同一個前提不能寫兩次；定義的 @given 再寫一次區塊裡的前提、參數或定義取了前提的名字，都是錯誤。
  • 編輯器在每個定義旁顯示它拿到的 @given(…)。只有一個定義要用的前提照舊寫 @given。

3.3 方法與 self

Section titled “3.3 方法與 self”

名字帶前綴、第一個參數叫 self 的定義是方法，用 x.f(…) 呼叫：

  • self 的型別由前綴決定（Tree.size 的 self 是 Tree(A)，型別參數照型別宣告的參數名）；也可以明寫 self: Tree(A)。
  • x.f(a) 在 x 的型別是 T、有 T.f 時就是 T.f(x, a)：x 放在 T.f 的第一個明確參數。可以連鎖：x.size().toString()。List.map 的第一個明確參數是函式，所以串列的 map 寫 map(f, xs)。record 的欄位照舊優先。

3.4 區域定義：where

Section titled “3.4 區域定義：where”
  • where { def … } 裡的定義只給這條定義用，可以遞迴、互相呼叫、使用外面定義的參數（count 的 start）。
  • 相互遞迴的頂層定義不用寫任何東西：同一個模組裡互相看得到（見 3.6）。

3.5 private

Section titled “3.5 private”

預設公開；private 只在這個模組看得到，可以加在 def、fact、type、record、interface 前面。

3.6 相互遞迴

Section titled “3.6 相互遞迴”

同一個模組裡的定義互相看得到，不需要 mutual；Cella 依參照分組。終止性照樣檢查。

3.7 上方標註的順序

Section titled “3.7 上方標註的順序”

定義的頭之上可以寫幾種行，順序是固定的（cella fmt 會排）：

  1. 說明 ///
  2. 工具標註：@cite、@steps、@simp、@infix、@model、@source、@derive、其他
  3. @given
  4. @requires
  5. @ensures／@shows
  6. 頭
  • @steps(N)：這條定義的檢查步數上限（預設依定義大小；需要時放寬）。
  • @simp：讓 simp() 策略用這條等式。@irreducible、@reducible 調整展開行為。
  • @derive(C, D)：寫在 type 上方，自動產生介面的實作（見 4.1）。

4. 型別

Section titled “4. 型別”

4.1 type

Section titled “4.1 type”
  • type 名字(參數) { 情況 … }：每個情況一行（同一行並列用逗號）；參數沒寫型別時是 Type。
  • 情況有資料時：node(left: Tree(A), value: A, right: Tree(A))。欄位名字：一個欄位可以省略名字（some(A)），兩個以上要有名字。
  • type 別名 = 型別：取別名。
  • @derive(DecEq, …) 寫在 type 上方：自動產生實作（見下）。
  • type 是好幾種情況，record 是一種形狀。

帶索引的型別：每個情況寫自己的結果型別，情況用到的隱式參數寫在情況的上方。

  • 有路徑建構子（高階歸納型別）的情況寫 loop: base =~= base（見 8）。
  • 自動產生：@derive(DecEq) 產生 == 用的判定；@derive(Json)（要 import json）產生 T.toJson、T.fromJson。

4.2 record

Section titled “4.2 record”
  • record 名字(參數) { 欄位: 型別 … }；每個欄位一行，同一行並列用逗號 { x: Nat, y: Nat }。
  • 建立：Point(x = 0, y = 0)（圓括號、=）。修改：p.with(y = 5)（得到一個新的值）。取欄位：p.x。
  • 每個 record 是自己的型別：兩個 record 有同名的欄位不會混淆。
  • record 裡可以宣告要滿足的 law：@shows(low <= high) 加 law ordered。

4.3 二元組與有名字的配對

Section titled “4.3 二元組與有名字的配對”
  • (A, B) 是二元組的型別（三個以上就是 (A, (B, C))），值寫 (3, 4)，取分量用 .first、.second。
  • 拆開用 match 的樣式 (a, b)。
  • 第二個分量的型別依賴第一個的值時給名字：(n: Nat, p: P(n))，值也可以寫成 (n: 1, p: …)。值的名字是寫給讀者的，各部分依位置對應型別的各部分。

4.4 無限的資料：lazy record

Section titled “4.4 無限的資料：lazy record”
  • lazy record 由「能觀察到什麼」定義，可以無窮；大小由檢查器推，不用寫。讀欄位 s.head。推出來的大小是隱式參數 i，要指定時用名字給：Stream(Nat, i = inf)、tail(s, i = inf)。
  • type 與 record 分開：lazy 只加在 record。
  • 建立 lazy record 的值這一版還沒有（見 13）。

4.5 interface 與 implement

Section titled “4.5 interface 與 implement”
  • interface 名字(參數) { 成員 … }：欄位 empty: T、操作的簽章 combine(a: T, b: T) -> T、要滿足的 law。操作可以帶預設實作 def f(x: T) -> T { … }。
  • implement 介面(型別) { 成員 = 實作 … }：combine(a, b) = a + b；law 寫 law 名字(參數) by 理由，和 fact 一樣。
  • 要指定實作的名字：implement Ord(Nat) as natLE { … }。
  • @given(T, Monoid(T))：需要 T 有 Monoid 的實作，由 Cella 找出來；要點名時 @given(m: Monoid(T))。

4.6 型別的運算

Section titled “4.6 型別的運算”
  • A -> B：函式型別；(A, B) -> C 是收兩個引數的函式；收一個二元組寫 ((A, B)) -> C。
  • (x: A) -> B(x)：結果的型別依賴參數的值。名字沒用到時寫 A -> B。
  • Type、Type(1)：型別的型別（宇宙）。需要層級時 @given(u: Level) 加 Type(u)。
  • (e: T)：型別標註。
  • List(Int)、Vec(A, n)：把引數給型別函式，和函式呼叫同一個寫法。

5. 運算式

Section titled “5. 運算式”

5.1 呼叫與運算子

Section titled “5.1 呼叫與運算子”
  • 呼叫一律圓括號：f(x, y)、List(Int)；沒有引數的寫 f()。方法呼叫 x.f(y)（見 3.3）。
  • 運算子是固定的一組（不能自訂新符號）：
優先序（由鬆到緊） 運算子
最鬆 x => e（lambda）、A -> B
or
and
not
===、=~=、==、!=、<、<=、>、>=
a word b（@infix 宣告的英文字）
+、-
*、/、%
-x（一元負號）
最緊 呼叫、.
  • 邏輯用 and、or、not，都是字；== 是布林的比較（!= 是它的否定），=== 是相等的陳述，=~= 是路徑（見 6.1）。
  • 運算子經介面多載：+ 是 Add、- 是 Subtract（放在值前面是 Negate）、* 是 Multiply、/ 是 Divide、% 是 Modulo（import operators）；<= 是 LE，< 是 LessThan，== 在要布林的位置由 DecCEq 判定（import ordering.relations）。
  • 自己的型別寫 implement Add(Money) { add(a, b) = …, law addAssoc(a, b, c) by … } 就能用 +，也能傳給 @given(T, Add(T)) 的函式。Add 與 Multiply 帶結合律的 law，要在 implement 裡證明；其他四個沒有 law（a - b + b === a 對 Nat 就不成立）。
  • 不想證明 law，或運算本來就不結合時，定義 def Money.add(a: Money, b: Money) -> Money（sub、mul、div、mod、neg 同理）：+ 先找它，但這樣的型別不能傳給 @given(T, Add(T)) 的函式。
  • 串列相接用 xs + ys（import operators）；它帶結合律，append(xs, ys) 是同一件事。
  • import operators 之後，裸寫的 add(a, b) 有兩個意思（Nat.add 與介面的操作），會報歧義：寫全名 Nat.add 或 Add.add。運算子不受影響。
  • 比較可以連寫：0 <= b < width（每一段都比）。
  • 英文字的中間寫法：定義上方標 @infix，之後可以寫 a xor b：

@infix 寫在定義的上方，例如 def xor(a: Bool, b: Bool) -> Bool { … } 上方標 @infix，之後 a xor b == false 是 xor(a, b) == false。定義要剛好有兩個明確參數；沒有標 @infix 的名字不能寫在中間，訊息會說要標。同一個檔案裡寫在定義之前的也算，import 來的也算。

中綴字的規則：和比較混用不用括號（比較永遠最後算）；和算術或 to 混用一定要括號；同一個字連用左結合；兩個不同的中綴字混用要括號。中綴字要和左右兩邊寫在同一行。

5.2 lambda

Section titled “5.2 lambda”
  • x => e；多個參數 (a, b) => e；可以標型別 (x: Nat) => e。
  • => 右邊要多行時寫大括號區塊，最後一行是結果。
  • 型別由期望推出時不用寫參數型別。

5.3 let

Section titled “5.3 let”
  • let 名字 = 值、let 名字: 型別 = 值；區塊裡的每一行 let 依序綁定，最後一行是結果。

5.4 if

Section titled “5.4 if”

if 條件 { 值 } else { 值 } 是運算式，兩個分支都要寫；條件是 Bool。分支要多行時直接在大括號裡寫。if 後面接的只能是 {。

5.5 match

Section titled “5.5 match”
  • match 值 { 樣式 => 結果 … }：分支一行一個（同一行並列用逗號）；分支要多行時 => { … }。
  • 樣式：名字（綁定）、_、建構子加子樣式 node(l, _, r)、數字、k + 1、二元組 (a, b)、串列 []、[x, ...rest]。
  • 建構子不用寫型別前綴（import 之後依型別解析）；會撞名時寫 Vec.empty、或 from m import empty。單獨的小寫名字會被當成新變數，有同名的建構子時會報錯並提示。
  • 同時對好幾個值：match (a, b) { (x, y) => … }。
  • 對運算式 match 時，運算式在每個分支裡換成那個建構子。
  • 需要明寫目標型別時：match n returning (m => Vec(Nat, m)) { … }。
  • 不可能的情況：呼叫消去 i.impossible()（標準庫補上之前用 Fin.absurdZero(i)），不寫新語法。

5.6 串列

Section titled “5.6 串列”

[a, b, c]；換行時每一項都加逗號，最後一項也加。樣式 []、[x, ...rest] 見上。

5.7 字串與字面量

Section titled “5.7 字串與字面量”
  • 自然數：0、42、1_000_000（底線只是分隔）、0xFF、0b101；很大的數也可以。負數 -3。
  • "…"：一般字串，不跨行；跳脫 \n \t \r \" \\。大括號照字面（名字在作用域內時檢查器會提示要插值請寫 f"…"）。
  • f"…{e}…"：字串插值，{e} 經 ToString 轉成字串；{{、}} 是大括號本身。

5.8 待填的洞

Section titled “5.8 待填的洞”

todo("說明") 或 todo() 是留給之後寫的地方。有 todo 的定義判決不能是 Accept；檢查結果會列出它的型別與前後文。_ 是讓 Cella 推出來的部分。

5.9 換行與逗號

Section titled “5.9 換行與逗號”

同一行並列用逗號、換行時的規則：

位置 換行時
( ) 裡的參數、引數、二元組；[ ] 裡的串列 每一項都加逗號，最後一項也加（結尾逗號）
{ } 裡的區塊、情況、欄位、match 分支 換行就夠，不加逗號；同一行並列時用逗號
  • 接續上一行：行首是 ===、==、<=、+、.、->、else、by 這類只能接在後面的記號時，算同一個式子。
  • 行首的 - 是一元負號，不算接續；長算式換行時運算子留在上一行結尾（cella fmt 會這樣排）。
  • 寬進嚴出：換行時多加或少加的逗號剖析器都收，cella fmt 印成上面的標準格式。
  • 運算子之後、括號裡面換行都不用另外處理；只有 { } 的區塊用換行分隔敘述。

5.10 節點標籤

Section titled “5.10 節點標籤”

@node("標籤") e 把 e 標上產生這段程式的工具的節點名字：cella check --json、cella holes --json 的錯誤、洞與 unknown 帶回所在的最內層標籤（"node" 欄位）。標籤是透明的，意思就是 e。範圍和一元 - 的運算元一樣：@node("a") x + 1 只標 x。

6. 證明

Section titled “6. 證明”

6.1 相等

Section titled “6.1 相等”

三個寫法，各一個意思：

寫法 意思 型別
a == b 布林的比較，由 DecCEq 判定 Bool
a === b a 等於 b 這個陳述（相等的證明的型別，identity 模組的 Eq） 型別
a =~= b 從 a 到 b 的路徑（見 8） 型別
  • === 的證明是 refl（兩邊算出來一樣），或由引理、策略得到；by compute 由 kernel 算兩邊是否相同。它不碰路徑，所以 mode core 的檔案也能用。
  • h: a === b 的方法：h.sym() 反向、h.trans(k) 接起來、h.cong(f) 兩邊同套 f。
  • == 要型別有 DecCEq 的實例：它帶兩條 law（判定為真就相等、相等就判定為真，都是 ===），所以判定的結果和陳述一致；Nat、Int、String 有實例，自己的型別寫 implement DecCEq(T)。沒有實例的型別是錯誤，訊息會說要哪個實例。
  • 在型別的位置寫 == 是錯誤，訊息會說寫 ===；在要布林的位置寫 === 也是錯誤（它是陳述）。
  • (a == b) == true 是錯誤：拿掉 == true。
  • a != b 是 not (a == b)；相等的否定寫 (a === b) -> Empty。

6.2 fact 與 @shows

Section titled “6.2 fact 與 @shows”
  • fact 名字(參數) 上方的 @shows(…) 是要證的命題。fact 沒有 @shows 時是錯誤。
  • 本體是 by compute、by 引理(…)、by { 策略 }，或一個區塊（兩欄式、match）。
  • 判決的斷言：@shows(…) 加 fact 名字 by compute 由 kernel 算；另一種寫法是 test（這一版還沒有）。

6.3 兩欄式

Section titled “6.3 兩欄式”

左邊是式子，右邊是理由；第一行之後行首寫 ===：

  • 每一步寫 === 下一個式子 by 理由。理由是引理的呼叫、compute 或 { 策略 }。路徑的兩欄式每一步寫 =~=；同一個兩欄式不混用兩種。
  • 同一步要在兩邊同套一個函式：.cong(f)，例如 by addZero(k).cong(n => n + 1)。

6.4 策略：by { … }

Section titled “6.4 策略：by { … }”

by { … } 裡一行一步，每一步像呼叫函式（沒有引數也要寫 ()），不用 ;。

策略 意思
intro()、intro(x)、intro(x, y) 把假設或參數移進上下文
exact(e)、apply(f) 用這個項（或這個函式）
rfl() 兩邊相等
induction(n)、cases(n) 對 n 分情況
rewrite(p)、rewrite(p, reverse = true)、rewrite(p, at = h) 用等式改寫
simp()、simp(a, b)、simp(only = [a, b]) 用 @simp 的等式化簡
ring()、omega()、linarith()、polyrith()、norm_num() 算術（要 import 對應的模組）
decide() 由計算判定
linsolve()、linsolve([u1, u2])、linsolve([u1, u2], ["r1", "r2"]) 線性方程組的解（要 import linsys；列出的是未知數與方程的名字，判決用它們說明缺什麼）
constructor()、left()、right()、exfalso()、contradiction() 邏輯
try t、repeat(t)、first(t1, t2)、all(t) 組合策略
let h: T = 證明 中途證一個事實

6.5 帶證明的條件

Section titled “6.5 帶證明的條件”

if a == b as h { … } else { … }：條件是布林的比較，h: a === b 在第一個分支裡可以用（由 DecCEq 的 law 得到）。

另一種寫法是 match decide(a === b) { yes(h) => …, no(h) => … }（要 import decidable），no 的分支也帶證明（(a === b) -> Empty）。

7. 終止

Section titled “7. 終止”

遞迴預設要結構遞減（在參數的子項上遞迴；字典序與相互遞迴會自動找）。不是在子項上遞迴時，需要提供量度，這一版還沒有這個寫法（見 13）。

8. 路徑與 cubical

Section titled “8. 路徑與 cubical”

Cella 的核心是 Cubical 型別論（CCHM）。路徑是區間上的函式：

  • path i => …：路徑（path 只在這個位置是關鍵字）。取點：p.at(i)，1 - i 反向。
  • a =~= b 是路徑型別。要 mode cubical（或不宣告 mode）；Eq.toPath(h) 把 h: a === b 變成路徑。
  • transport(x, along = line)、transport(x, along = line, fixedWhen = i == 0)：沿著型別的線運送。
  • compose(base = b, sides = { i == 0: path j => u, i == 1: path j => v })：sides 的鍵是條件。
  • a =~= b over (i => A(i))：不同型別之間的路徑。
  • univalence(e)：把型別等價變成路徑（e: Equiv(A, B)）。
  • Glue(A, …)、Sub(A, φ, u)：一般的呼叫。

高階歸納型別：一個情況的型別是路徑。

模式比對的分支必須是端點影像之間的路徑，Cella 會檢查。

9.2 extern def

Section titled “9.2 extern def”
  • extern def 由執行環境提供；能執行（assume 不能）。判決把它列成「外部函式」的假設。

10. 使用次數、模態、mode

Section titled “10. 使用次數、模態、mode”

10.1 分級

Section titled “10.1 分級”

分級名寫在參數名前：ghost（抹除：只在型別裡用）、once（恰好一次）、many（任意次，預設）。

函式型別的參數帶分級時一定寫名字：(once file: File) -> Unit。

自己的分級：type Budget { … } 加 implement Grades(Budget) { … }（半環規則是 law），用 mode careful extends core { grades = Budget } 啟用（見 10.3）。

10.2 型別模態

Section titled “10.2 型別模態”
  • modality 名字 from m to n：宣告模態。名字(B) 是模態型別，名字.of(a) 放進模態（a 在鎖之下檢查），match 的樣式 名字.of(x) 拆開。
  • 參數前寫模態名：def back(sharp x: B)；和分級同一個槽位。

10.3 mode

Section titled “10.3 mode”

mode 決定一個定義可以用哪些功能：

  • 預設 core，不寫。其他的檔案第一行寫 mode 名字（mode cubical 用路徑與高階歸納型別，mode runtime 用 IO 與外部呼叫）。
  • 單一定義：@mode(core) 寫在定義上方。
  • 自訂：mode careful extends core { grades = Budget }。

11. 會跑的程式

Section titled “11. 會跑的程式”

有 main: IO(Unit)（或 def main() -> IO(Unit)）的檔案可以執行。

  • 在回傳型別是某個 monad（IO、Option、Either(E)、你自己實作 Monad 的型別）的函式裡，let x = try e 取出 e 的結果，整個區塊失敗時失敗；行首的 try e 執行並丟掉結果；最後一行是整個區塊的值。

自己的型別要能這樣用，寫 implement Monad(Chk) { pure(a) = …, bind(m, f) = … }。

12. cella fmt 與 cella migrate

Section titled “12. cella fmt 與 cella migrate”
  • cella fmt 檔案… 就地格式化；cella fmt --check 檔案… 不改檔，有要改的就列出並以非零結束。
  • 標準格式是唯一的：行寬 100；函式本體一律換行；短的型別本體放得下就一行；match 分支的 =>、情況的 (、record 欄位的 : 在同一個區塊裡對齊。
  • cella migrate <路徑…> 把舊寫法的檔案轉成新寫法；每個定義的核心項逐一相同才寫回。

13. 這一版還沒有

Section titled “13. 這一版還沒有”
