cfamily.Leaving

Section titled “cfamily.Leaving”

How the current statements are left: done, by return (with the value), break, continue, or goto to a label in a block.

cfamily.Frame

Section titled “cfamily.Frame”

What to do after the current statements.

cfamily.Outcome

Section titled “cfamily.Outcome”

How a run ended: with an exit code, stopped (undefined behavior, a dialect’s reason), out of fuel inside an expression, at a statement that did not check (the type query’s collect mode), or before it began at a construct not supported yet (not an error in the program).

cfamily.Configuration

Section titled “cfamily.Configuration”

A configuration: running statements, leaving, or finished; or a trial run first, then going on from how it ended (a dialect compares what a choice the implementation makes changes, as whether unwinding the stack before a termination changes the output).

cfamily.RunExtension

Section titled “cfamily.RunExtension”

How a dialect runs what the core does not know. Each defaults to nothing.

  • statement: its own statements (node, tag, types, expressions, statements), with the core’s evaluator;
  • frame: how leaving passes one of its frames;
  • ending: what to run before an object of a declaration ends (C++’s destructor), none when nothing; it is given the program’s functions (whether the destructor is one) and whether the object ends because an exception leaves its scope (C++’s cleanup of a half-constructed object’s members runs only then);
  • uncaught: how a run ends when an exception leaves main uncaught (a dialect with exceptions raises them by leaving with raising; the scopes it leaves end as for any leaving, the calls pass it to their callers).

cfamily.RunExtension.empty

Section titled “cfamily.RunExtension.empty”

The extension of a dialect without statements or frames of its own.

cfamily.RunDialect

Section titled “cfamily.RunDialect”

What running needs: the dialect’s evaluation, library and extension, the program’s functions and the one a run starts at (main, or a board core’s own).

cfamily.RunDialect.evaluator

Section titled “cfamily.RunDialect.evaluator”

The core’s evaluator for a dialect.

cfamily.State.addNotes

Section titled “cfamily.State.addNotes”

The state with notes added.

cfamily.Configuration.after

Section titled “cfamily.Configuration.after”

Going on with an evaluated value (its notes added to the state), or finishing at a stop.

cfamily.Configuration.stop

Section titled “cfamily.Configuration.stop”

A stop at a node.

cfamily.Frame.push

Section titled “cfamily.Frame.push”

The frames with the rest of a sequence pushed (nothing when it is empty).

cfamily.Frame.either

Section titled “cfamily.Frame.either”

The first of two options that is some.

cfamily.TypedStmt.hasLabel

Section titled “cfamily.TypedStmt.hasLabel”

Whether a statement carries a label.

cfamily.TypedStmt.splitAt

Section titled “cfamily.TypedStmt.splitAt”

The statements before a label and from it on.

cfamily.State.inInnermost

Section titled “cfamily.State.inInnermost”

Whether a declaration is in the innermost scope.

cfamily.State.skipped

Section titled “cfamily.State.skipped”

The declarations a jump forward skips: their objects exist from the block’s start, uninitialized (C11 6.2.4p6).

cfamily.CheckedFunction.named

Section titled “cfamily.CheckedFunction.named”

The function with a name.

cfamily.CheckedFunction.bodyOf

Section titled “cfamily.CheckedFunction.bodyOf”

The body of the function with a name.

cfamily.Frame.functionBody

Section titled “cfamily.Frame.functionBody”

The body of the function the frames are in (the innermost call; none is the entry, of the name given).

cfamily.State.local

Section titled “cfamily.State.local”

The scopes but the last (the global one).

cfamily.State.global

Section titled “cfamily.State.global”

The last scope (the global one).

cfamily.State.withGlobal

Section titled “cfamily.State.withGlobal”

Scopes with the outermost (global) one replaced.

cfamily.State.backTo

Section titled “cfamily.State.backTo”

Back in the caller: the callee’s scopes released, the caller’s restored (and its calls), the result (if any) in the target, which is an object from then on.

cfamily.State.declareTarget

Section titled “cfamily.State.declareTarget”

A temporary for a result declared in the current scope (uninitialized).

cfamily.State.bindParameters

Section titled “cfamily.State.bindParameters”

The parameters declared with the arguments’ values.

cfamily.State.reserveTarget

Section titled “cfamily.State.reserveTarget”

A temporary for a function’s result reserved in the current scope: no object until the call returns (one that leaves by an exception leaves none to end, [except.ctor]p1).

cfamily.Configuration.call

Section titled “cfamily.Configuration.call”

A call: the target reserved in the caller’s scope, the callee’s body in a scope of its own over the global one; the call’s node is the innermost of the calls the run is in.

cfamily.Leaving.isRaising

Section titled “cfamily.Leaving.isRaising”

Whether leaving is an exception on its way out.

cfamily.Ending

Section titled “cfamily.Ending”

What the dialect runs before an object ends: the object’s declaration and block, and the statements.

cfamily.State.firstEnding

Section titled “cfamily.State.firstEnding”

The most recent object of a scope the dialect has something to run for before it ends (an object only reserved, not yet constructed, has nothing).

cfamily.State.toEnd

Section titled “cfamily.State.toEnd”

An object about to end, moved to a scope of its own (State.isolate) and marked as being destroyed: const does not apply while its ending runs (C++ [class.dtor]), as while it is constructed.

cfamily.Configuration.arrive

Section titled “cfamily.Configuration.arrive”

A goto arriving at its label’s block: the objects declared from the label on that exist end first, the latest first (a jump back past a declaration ends its object, C++ [stmt.dcl]p2; each ending runs as in leaving a scope, then the jump arrives again); then from the label on, with the declarations it skipped.

cfamily.Configuration.leaveScope

Section titled “cfamily.Configuration.leaveScope”

Leaving a scope: an object’s cleanup first (the object moves to a scope of its own, the cleanup runs, that scope ends with the object’s block, then leaving resumes at the same frame), else the scope ends.

cfamily.Leaving.exitCode

Section titled “cfamily.Leaving.exitCode”

The exit code of a program’s end: main’s result, or 0 when main’s body ends (C11 5.1.2.2.3).

cfamily.Leaving.result

Section titled “cfamily.Leaving.result”

The value a call returns: the return’s, none when the body ends (using it reads an indeterminate value).

cfamily.Frame.nextRound

Section titled “cfamily.Frame.nextRound”

A loop’s next round: the statements each round ends with, then the check.

cfamily.Frame.leave

Section titled “cfamily.Frame.leave”

Leaving passes one frame.

cfamily.Address.isPrefix

Section titled “cfamily.Address.isPrefix”

Whether one path is a prefix of another.

cfamily.Held.coversPath

Section titled “cfamily.Held.coversPath”

Whether a path is in what a held array covers: it contains the array, or it is in one of the held elements (in the object, for a held whole object); an empty range covers nothing.

cfamily.Held.covers

Section titled “cfamily.Held.covers”

Whether a held array covers an address.

cfamily.Value.sameScalar

Section titled “cfamily.Value.sameScalar”

Whether two scalar values are the same, when the model can tell: integers, pointers and functions.

cfamily.State.altersHeld

Section titled “cfamily.State.altersHeld”

Whether storing a value at an address alters an array qsort or bsearch holds (C11 7.22.5p3): the address is in it and the value there is a different one. Storing the same value alters nothing; a value the model cannot compare (a floating value, a whole struct, an indeterminate one) is let through, so this misses some writes but never rejects one that does not alter the array.

cfamily.TypedExpr.copiedFrom

Section titled “cfamily.TypedExpr.copiedFrom”

Where a whole object being assigned is read from: the lvalue of a struct or union assignment’s right side (read whole, or a member or dereference of struct or union type); none for any other value.

cfamily.State.placesIn

Section titled “cfamily.State.placesIn”

The places of two subobjects of a block, by the layout of the block’s type (none when the type has no shape).

cfamily.Placed.overlapsPartly

Section titled “cfamily.Placed.overlapsPartly”

Whether two places share bits without being the same bits.

cfamily.State.overlapsPartly

Section titled “cfamily.State.overlapsPartly”

Whether the object written and the object its value is read from overlap other than exactly (C11 6.5.16.1p3, C++17 [expr.ass]p8): in the same block, their bits by the block’s layout shared without being the same. Exact overlap with an incompatible type cannot be written (the assignment’s sides have compatible types); addresses of bytes, and blocks whose type has no shape, are let through.

cfamily.Address.overlap

Section titled “cfamily.Address.overlap”

Whether two addresses overlap: the same block with one path a prefix of the other (a struct and its member); a byte of an object overlaps the object and what is in it, another byte only when it is the same one.

cfamily.TypedClause.startingAt

Section titled “cfamily.TypedClause.startingAt”

The statements of a switch from the clause with the value (falling through the rest), or from default.

cfamily.Ty.cellLimit

Section titled “cfamily.Ty.cellLimit”

The most cells (scalars) an object the model makes may have: 2^20. A larger one would make the host run out of memory before the run ends (the elements are kept one by one).

cfamily.Object.repeated

Section titled “cfamily.Object.repeated”

An array object of count copies of an element.

cfamily.Configuration.withinCells

Section titled “cfamily.Configuration.withinCells”

The run going on (go, called only after the check: making the object is what the limit prevents) unless an object of a count of cells is more than the model keeps.

cfamily.State.allocateArray

Section titled “cfamily.State.allocateArray”

malloc and calloc: size bytes are size / elementSize whole elements (a remainder is never used), in a new block; the pointer to its first element goes into x.

cfamily.Memory.mallocStart

Section titled “cfamily.Memory.mallocStart”

The block a pointer starts if it is the start of a block malloc made that is alive (what free and realloc take, C11 7.22.3.3p2, 7.22.3.5p3).

cfamily.Configuration.free

Section titled “cfamily.Configuration.free”

free: NULL does nothing; else it must be the start of a block malloc made that is alive (C11 7.22.3.3p2).

cfamily.Memory.elementsOf

Section titled “cfamily.Memory.elementsOf”

A block’s elements (none for a block that is not an array).

cfamily.State.reallocated

Section titled “cfamily.State.reallocated”

realloc’s new block for a pointer into x: size bytes of element, the first objects moved from block b (the rest indeterminate), b released (C11 7.22.3.5p2).

cfamily.Configuration.reallocate

Section titled “cfamily.Configuration.reallocate”

realloc: NULL is malloc; else the pointer must be the start of a block malloc made that is alive (C11 7.22.3.5p3); size zero is implementation-defined (C11 7.22.3p1); else the block moves to one of the new size.

cfamily.Configuration.returned

Section titled “cfamily.Configuration.returned”

The result of a library call delivered to its target.

cfamily.Configuration.stored

Section titled “cfamily.Configuration.stored”

Going on with a value assigned to a declaration’s object.

cfamily.Configuration.returnWith

Section titled “cfamily.Configuration.returnWith”

Leaving by returning a value.

cfamily.Configuration.declaration

Section titled “cfamily.Configuration.declaration”

Declarations, assignments and the objects’ lifetimes.

cfamily.Configuration.control

Section titled “cfamily.Configuration.control”

Control: branches, loops, blocks, switch, jumps.

cfamily.Configuration.effect

Section titled “cfamily.Configuration.effect”

Calls, the library, and the checks the checker placed.

cfamily.Configuration.step

Section titled “cfamily.Configuration.step”

One move.

cfamily.CheckedFunction.entryBody

Section titled “cfamily.CheckedFunction.entryBody”

The entry’s body (of the name given); with parameters (main’s argc and argv), inside a scope (no node: the debugger does not stop at it) that first gets them from the arguments.

cfamily.Configuration.start

Section titled “cfamily.Configuration.start”

The start of a run on the program’s arguments: one block with the globals initialized in order (as one statement, so the first move runs them and a step stops next at main’s body), then main’s body; main’s return leaves the block, which ends the globals the last first (C++ [basic.start.term]p1: their destructors after main returns). The block’s scope is the global one (the outermost, which a called function sees): the run starts with no scope.

cfamily.State.argumentString

Section titled “cfamily.State.argumentString”

A string as a character array of its own (with the null), and its block.

cfamily.State.argumentStrings

Section titled “cfamily.State.argumentStrings”

The strings as arrays of their own, and their blocks in order.

cfamily.State.arguments

Section titled “cfamily.State.arguments”

argc and argv declared: each argument a string of its own that the program may change, argv an array of pointers to them ending in NULL (C11 5.1.2.2.1p2).
