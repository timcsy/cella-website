cpp.Cpp.everyHeader

Section titled “cpp.Cpp.everyHeader”

libstdc++’s <bits/stdc++.h> (not a standard header; libc++ has none): every standard header it includes under C++17, the C library’s <cxxx> headers and the C++ ones (GCC’s include/precompiled/stdc++.h).

cpp.Cpp.rules

Section titled “cpp.Cpp.rules”

C++17’s rules.

cpp.Effects.withoutReceiver

Section titled “cpp.Effects.withoutReceiver”

Effects without what they do to a receiver.

cpp.Cpp.isThis

Section titled “cpp.Cpp.isThis”

Whether an expression is this.

cpp.Cpp.atReceiver

Section titled “cpp.Cpp.atReceiver”

Whether an lvalue is (a part of) the object a member function is called on: a member used alone, this->m, *this, and their members and elements.

cpp.Cpp.readingReceiver

Section titled “cpp.Cpp.readingReceiver”

Reading the receiver only.

cpp.Cpp.writingReceiver

Section titled “cpp.Cpp.writingReceiver”

Writing the receiver only.

cpp.Cpp.readingGlobal

Section titled “cpp.Cpp.readingGlobal”

Reading a global only.

cpp.Cpp.writingGlobal

Section titled “cpp.Cpp.writingGlobal”

Writing a global only.

cpp.Cpp.objectEffects

Section titled “cpp.Cpp.objectEffects”

What reading (or writing) the object a member function is called on, the object o (through a pointer when arrow), is to the caller: its own receiver, memory elsewhere, a global, or a local (nothing).

cpp.Cpp.memberCallEffects

Section titled “cpp.Cpp.memberCallEffects”

The effects of a member function’s call on the object o: evaluating the object and the arguments, the member functions of the name (by their short name), with what they do to their receiver done to o.

cpp.Cpp.shortName

Section titled “cpp.Cpp.shortName”

A function’s short name, by which a member function is called: after the last ::, without an overload’s #k.

cpp.Cpp.effects

Section titled “cpp.Cpp.effects”

The effects of C++: the core’s, with iostream’s input and output (writing to a stream, reading from cin, getline), a member function’s reads and writes of its receiver (the object it is called on: a member used alone, through this) and its calls’ on their objects, and a function the program does not define reading memory elsewhere.

cpp.Cpp.types

Section titled “cpp.Cpp.types”

C++’s types: references, and a class name as its struct.

cpp.Cpp.assign

Section titled “cpp.Cpp.assign”

C++’s assignment conversion: its own (references, classes passed by address, bases), else the core’s.

cpp.Cpp.choosing

Section titled “cpp.Cpp.choosing”

What choosing a constructor uses in C++, with a checker of expressions.

cpp.Cpp.picking

Section titled “cpp.Cpp.picking”

How C++ chooses among overloaded member functions, with a checker of expressions.

cpp.Cpp.firstOf

Section titled “cpp.Cpp.firstOf”

The first of the tries that gives a result, in order; a try after it is not made.

cpp.Cpp.nameParts

Section titled “cpp.Cpp.nameParts”

A lowered name’s parts: what comes before the last :: (none without one), and the name after it without a # suffix (A::f#1 is A and f).

cpp.Cpp.mismatchOf

Section titled “cpp.Cpp.mismatchOf”

What a call whose arguments match no function is rejected with, as clang says it: no matching member function for a class’s member function (lowered as C::f), no matching function for any other; by the name without its qualifier, as declared.

cpp.Cpp.expressions

Section titled “cpp.Cpp.expressions”

C++‘s expressions: a variable or call of reference type designates what it refers to (such a call is an lvalue); sizeof of a reference type is its referent’s; this, a member used alone, member function calls and members’ access; a call whose arguments do not match the function is no matching function (overload resolution with one candidate).

cpp.Cpp.unmodeled

Section titled “cpp.Cpp.unmodeled”

A call of a function of the standard library the branch has no model of (a name std declares, that nothing in the program or the library defines): not supported yet, which is not an error in the program. Written std::f (as names resolution writes one using namespace std makes visible), or without it for a function the C headers declare in the global namespace (srand of ); any other name nothing declares is undeclared. The allocation functions the core checks by its own rules have a model.

cpp.Cpp.call

Section titled “cpp.Cpp.call”

A call C++ gives a meaning by name before the program’s functions: a static member function, else a function of the standard library it has no model of.

cpp.Cpp.conversions

Section titled “cpp.Cpp.conversions”

C++’s conversions: a value bound to a reference, an argument for a class parameter passed by address, a derived class’s pointer or object as its base’s; else a user-defined conversion (a converting constructor, a conversion function).

cpp.Cpp.checkingFor

Section titled “cpp.Cpp.checkingFor”

How C++ checks expressions on a target (an Arduino board’s, or LP64): C++17’s rules with the core’s C standard library ([library.c]).

cpp.Cpp.sourceLevel

Section titled “cpp.Cpp.sourceLevel”

The passes on a C++ program’s own syntax (and the types the type query puts in its holes): its namespaces flattened (a possible collision noted at the start of the entry, of the name given), std::ostream’s class added if it is used, the standard library’s functions it calls and std::type_info’s class (when it uses typeid) generated.

cpp.Cpp.sourceItems

Section titled “cpp.Cpp.sourceItems”

The items of a program after the passes on its own syntax (to answer a request: nothing runs, so no entry).

cpp.Cpp.definesTypes

Section titled “cpp.Cpp.definesTypes”

Whether an item is a class that defines a type (a class, a union, an enumeration or a member typedef in it): only then is there something to unnest or qualify after instantiation (most programs have none, and unnesting walks every item). A member typedef’s name used in the class (pair<iterator, bool>) is qualified by the class there.

cpp.Cpp.nestedInInstances

Section titled “cpp.Cpp.nestedInInstances”

The classes class templates’ instances define unnested as the program’s own were before instantiation (Names.lifted: Box<int>::Cell, [temp.mem.class]), and a member type naming one of them the class (instantiation writes Box<int>::Cell as a typedef’s name).

cpp.Cpp.prepare

Section titled “cpp.Cpp.prepare”

A C++ program lowered before it is checked: its namespaces flattened, std::ostream’s class added if it is used, the standard library’s functions it calls and the standard exceptions it uses generated, its class templates instantiated, its lambdas as objects of classes of their own, its overloaded functions renamed, its classes lowered.

cpp.Cpp.befriended

Section titled “cpp.Cpp.befriended”

Whether a function is the one a friend declaration names: its name (without the overload’s number) and its parameters’ types as written.

cpp.Cpp.friendsIn

Section titled “cpp.Cpp.friendsIn”

Each class’s friends ([class.friend]): the functions it names (as lowered, by their signatures) and the classes.

cpp.Cpp.tables

Section titled “cpp.Cpp.tables”

C++’s tables from the prepared items.

cpp.Cpp.lazy

Section titled “cpp.Cpp.lazy”

Whether a function is checked only if it is used: one of a library written in C++ (CppTables.library: the program calls few of its functions), a member function of a class template’s instance (whose name has template arguments, C<args>, [temp.inst]p11: a member of an instance is instantiated only when used) or of a std class (the implementation’s, [namespace.std]), or a function of namespace std that is no class’s member; never a destructor, which the end of an object’s scope calls when the run gets there, nor the run’s entry (the core never defers it). The class is the known one with the longest name the function’s starts with (a member of a nested one is its own).

cpp.Cpp.deferredInstance

Section titled “cpp.Cpp.deferredInstance”

Cpp.lazy for a member of a class template’s instance or of a std class, or a function of namespace std.

cpp.Cpp.programExtension

Section titled “cpp.Cpp.programExtension”

How C++ checks a program: its classes lowered first, their members’ access in the tables.

cpp.Cpp.statements

Section titled “cpp.Cpp.statements”

C++‘s statements: the streams’, a member function’s call as a statement, an object’s construction, and a reference’s declaration (it must be initialized).

cpp.Cpp.running

Section titled “cpp.Cpp.running”

How C++ runs its statements (the streams’, the objects’, the exceptions’), passes its frames (try blocks), ends its objects (their destructors) and ends a run with an uncaught exception.

cpp.Cpp.programDialectFor

Section titled “cpp.Cpp.programDialectFor”

C++’s checking of programs on a target.

cpp.Cpp.programDialect

Section titled “cpp.Cpp.programDialect”

C++’s checking of programs on LP64 (a program without a board).

cpp.Cpp.evaluation

Section titled “cpp.Cpp.evaluation”

How C++’s expressions are evaluated: the object containing a base subobject, the exception being handled.

cpp.Cpp.describe

Section titled “cpp.Cpp.describe”

How C++’s divergences are reported.

cpp.Cpp.dialectFor

Section titled “cpp.Cpp.dialectFor”

C++’s dialect on a target: its checking, and nothing extended in running.

cpp.Cpp.dialectWith

Section titled “cpp.Cpp.dialectWith”

C++’s dialect on a target, its environment given the host’s inputs (__cella_input, by the time each is given from).

cpp.Cpp.dialect

Section titled “cpp.Cpp.dialect”

C++ on LP64 (a program without a board).

cpp.Cpp.mismatch

Section titled “cpp.Cpp.mismatch”

Why a program is not one for this branch: it says it is C, or it is for a board (the Arduino branch’s).

cpp.Cpp.invalid

Section titled “cpp.Cpp.invalid”

An invalid program’s verdict: the reason as a problem of kind json.

cpp.Cpp.verdictOf

Section titled “cpp.Cpp.verdictOf”

The verdict of a C++ program run on an input for at most fuel steps.

cpp.verdict

Section titled “cpp.verdict”

The verdict JSON of a program given as JSON, run on an input for at most fuel steps.

cpp.Cpp.typeText

Section titled “cpp.Cpp.typeText”

How C++ writes types: bool, a class by its name alone, and a reference after what it refers to (int &, int &&).

cpp.Cpp.memberLabel

Section titled “cpp.Cpp.memberLabel”

How a debugger labels a member of a class: a base subobject by its class in angle brackets (as gdb does, <V>), the parts that keep the dynamic type and the virtual bases not at all, any other by its name.

cpp.Cpp.sequence

Section titled “cpp.Cpp.sequence”

Whether a class is one of the library’s containers a debugger shows by its elements: std::string as its characters, std::vector by its elements (gdb’s pretty printers do).

cpp.Cpp.spelling

Section titled “cpp.Cpp.spelling”

C++’s own spellings of types: a reference (T &), the library’s string and vector (std::vector<T>, as the library’s class and template’s instance, as the program’s are after Library.prepare); the types inside read by the whole reader.

cpp.Cpp.queryFor

Section titled “cpp.Cpp.queryFor”

C++’s type query on a target: its checking, how it writes types, the common types tried for a slot’s display (with std::string), and its own spellings.

cpp.Cpp.query

Section titled “cpp.Cpp.query”

C++’s type query on LP64.

cpp.Cpp.queryError

cpp.types
